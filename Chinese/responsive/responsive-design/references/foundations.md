# 可移植共享约定

必要摘录改编自 Shared Interface Design Foundations 0.2 与 Orchestration 0.3，读取日期为 2026-11-14。本文件支持独立使用；在目标项目中遵循其当前明确要求和既定约定。

- 围绕用户需要理解、决定和执行的工作组织信息。视觉层级服从任务重要性，密度服从内容和情境。
- 继承项目颜色、字体、间距、圆角、层级与组件。保持一个权威的产品 token 来源。本模块不选择通用字体、配色或断点尺度。
- 每个区域只有一名实现负责人。主控选择模块并统一整合 token；页面负责人拥有内容职责；组件负责人整合共享变体；交互与响应式专家定义并检查分配给自己的行为。
- 保持相关加载、空、错误、选中和禁用状态可用。在可恢复错误和布局变化中保留输入值与选择。主要操作需要可理解的名称、键盘访问和可见焦点。
- 使用既有 Modal、Toast、Tooltip 和 Drawer 约定。浮层内容、焦点与主要操作不能被遮挡。不要仅因空间更窄就改变确认或破坏性操作的语义。
- 区分页面滚动和局部滚动。内容换行、堆叠、移入展开区域或局部滚动时，保留重要信息与操作。
- 只读取当前任务需要的资源。用现有方法完成普通缺失能力，不假装另一个技能已经执行。
- 需要持续记录时，在目标项目中保存参考、采用决定、临时假设和实际验证。原始作者工作区不是运行时依赖。
- 区分观察与推断。不声称观察了未提供的状态或执行了未进行的测试。尊重用户修改边界；向共享内容负责人提出修改，而不是悄悄扩大局部修复。

这些摘录承载方法，不承载目标产品的视觉偏好。共享规范更新后，下次模块发布前应检查本快照是否仍然适用。
