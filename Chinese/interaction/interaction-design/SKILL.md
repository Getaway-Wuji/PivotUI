# 精细交互

让使用者清楚知道操作是否发生、目前处于什么状态、下一步如何继续。按任务选择必要状态和动画，输出可实现、可检查的行为约定；用户要求代码时完成约定范围内的实现。

## 接受范围与现有决定

先从任务和目标项目取得：要完成的操作、现有组件与业务状态、token 来源、允许修改的区域、目标设备及输入方式。主控已给出的内容直接继承；普通空缺采用有依据的局部方案，不要求逐项填写表单。

读取目标项目已提供的规范。本系列如提供 `design-system/FOUNDATIONS.md`、`design-system/ORCHESTRATION.md` 及相关模块记录，按目标项目根目录读取；这些是可选上下文，不寻找制作本 skill 的目录。独立使用且无规范时读 [共用方法摘编](references/foundations.md)。

保持页面主力的布局、信息顺序、业务规则和视觉方向，复用已有有效行为。局部修复可独立完成；组件、响应式或主控缺失时，由当前执行者补足必要工作。公共 token、组件接口或跨页行为的变化作为建议交给其负责人，不自行扩展修改范围。

## 先定义行为，再选择效果

1. 看现有行为与参考，标明可见事实、来源描述、代码核对、实际运行和补充建议。静态截图不能证明动态流程。研究规则见 [参考与证据](references/evidence.md)。
2. 对本次真正涉及的操作写出 **触发条件 → 状态变化 → 用户反馈 → 退出或恢复方式**；无证据的格子写明未知或建议。按下方子模块选择适用状态，无需让所有组件拥有全部状态。涉及消息或浮层选型时读取浮层子模块的适用/禁止表。
3. 处理远程提交、筛选请求、自动保存或批量操作时，读取 [异步与恢复](references/async-recovery.md)，先确定成功依据、重复操作、过期响应和失败后保留什么。
4. 需要动画时，优先从 React Bits 选择适合现有栈与任务的组件。先读 [React Bits 接入与选型](references/react-bits.md)，需要找组件再按类别查 [全量目录](references/react-bits-catalog.md)。按官方当前源码接入选中项，不预装全库。已有等效组件优先复用；原生轻量反馈或不适配的任务可用现有 CSS/组件能力，并说明取舍。
5. 结合 [动效与性能](references/motion-performance.md) 控制同屏活跃效果、输入替代和减少动态效果。用户偏好是大多数适用动画使用 React Bits，同时避免复杂效果堆叠；不把组件数量或视觉复杂度当成已测性能。

成功、错误、选中和权限来自实际业务状态。动画完成只代表表现结束，不能替代请求成功；示例代码中的假数据、计时器与演示完成状态不能直接当成真实业务逻辑。

## 按需读取与协作

核心入口负责共用边界与路由，`sub-skills/` 负责具体组件规则，`references/` 保留跨模块方法与来源索引，`assets/` 放按需采用的原创模板代码。子模块随本包分发，无需单独安装；不全量加载，也不因子模块互相引用而反复读取根入口。

| 当前问题 | 读取与产物 |
| --- | --- |
| Tooltip、Toast、Alert、Modal、Popconfirm、Drawer | [浮层组件](sub-skills/floating-components/SKILL.md)；先选正确类型，再定义出现、关闭、焦点与恢复 |
| 按钮 hover/focus/loading/disabled、按压与动作结果 | [按钮交互](sub-skills/button-interaction/SKILL.md)；区分输入反馈与业务状态 |
| 输入、校验、选择器、开关、滑块与筛选填写 | [表单交互](sub-skills/form-interaction/SKILL.md)；保留草稿、明确校验与提交 |
| 侧边栏、面包屑、当前项和命令菜单 | [导航交互](sub-skills/navigation-interaction/SKILL.md)；保持方向感、键盘与返回位置 |
| 通用状态区分、表格排序/选中/批量操作 | [状态与表格补充](references/interaction-patterns.md)；配合涉及的子模块 |
| 请求、提交、筛选竞态、乐观更新、撤销或批量结果 | [异步与恢复](references/async-recovery.md)；定义成功与失败路径 |
| 用户新参考或参考之间有冲突 | [参考与证据](references/evidence.md)；区分观察与补充，必要时参考 [首批规则](references/reference-rules.md) |
| React Bits 动画选型或接入 | [接入指南](references/react-bits.md)，按需查 [目录](references/react-bits-catalog.md)；记录具体组件、变体、来源与适配 |
| 复杂效果、低性能设备、触屏、减少动态效果 | [动效与性能](references/motion-performance.md)；给出启停条件与降级 |
| 主控交接、交付或行为检查 | [交接与验证](references/handoff-validation.md)；短约定和真实检查结果 |
| 缺少现有实现，需要状态按钮或结果消息模板 | [模板说明](assets/README.md)；按技术栈适配，保留真实结果与焦点逻辑 |

浮层选型采用用户的明确约定：Tooltip 仅补充说明，Toast 仅轻量结果且不呈现错误，Alert 持续呈现重要问题；Modal 用于不可逆确认或复杂信息，Popconfirm 只做低风险就近确认，Drawer 用于保留上下文的编辑且不承载简单表单/全屏任务。完整条件及替代路径在浮层子模块；React Bits 示例不覆盖这些规则。

同一组件由一个明确负责人整合实现。与 `component-system` 协作落实语义、接口与状态；与 `responsive-design` 协调触屏、滚动和不同输入方式。已被主力覆盖的内容直接沿用，不重复加载或相互转交。

## 交付

局部任务交付必要的行为说明或代码及检查结论；跨模块任务再附受影响组件、状态所有者、公共变化建议与未验证项。按 [交接与验证](references/handoff-validation.md) 验证键盘、焦点、提交反馈和恢复。仅设计规则时做代表性任务推演；存在实际运行界面时检查真实流程。不得将文档检查、源码核对或截图审阅称为运行通过。

独立调用示例：使用 `$interaction-design` 修复编辑抽屉的键盘焦点与保存失败恢复，沿用现有组件和样式，只为必要的状态切换选择动画。
