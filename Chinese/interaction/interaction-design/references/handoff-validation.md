# 交接与验证

用于主控分工或交付前核对。局部问题保留简短说明即可，不新增整套管理文档。

## 主控输入与模块输出

输入沿用已定的区域、目标任务、页面主力、token 来源、参考用途、允许修改的文件和设备。缺少普通辅助模块时由当前执行者补足，不能将用户转交给不存在的入口。

输出包括本次实际涉及的项目：

| 交接项 | 内容 |
| --- | --- |
| 范围与负责人 | 当前组件/区域及实现整合者；保留的布局与业务规则 |
| 行为 | 触发 → 状态 → 反馈 → 退出/恢复；键盘与焦点去向 |
| 状态所有者 | 父组件/表单/数据层谁决定选中、pending、结果；表现组件接收哪些事实 |
| 组件选型 | 复用的现有组件；React Bits 具体名称、变体、官方来源、核对标识与必要适配 |
| 设备与性能 | 触屏替代、减少动态效果、复杂效果运行范围、启停和降级 |
| 公共变化建议 | 新 token、共享接口或跨页行为及影响；交主控/组件负责人整合 |
| 验证 | 已执行的方法、结果、环境与未验证范围 |

能力发现依据实际 `SKILL.md` 的 name、description、资源和可完成范围，不需要额外注册文件。主控可以直接读取本 skill；不另定页面主力，不回调主控形成循环。React Bits 是组件来源，不替代项目内这些职责。

主控仍只需交接给 `interaction-design`；根入口在包内选择 floating-components、button-interaction、form-interaction 或 navigation-interaction。交接记录已读取的相关子模块即可，不将它们改成四个必装外部依赖。使用模板时注明采用了哪些文件及适配范围，入口见 [模板说明](../assets/README.md)。

## 代表性任务检查

按本次范围选择有意义的例子。规则创作时用独立任务推演选型与边界，界面实现时执行对应操作；两种证据分开。

| 任务 | 应能检查的结果 |
| --- | --- |
| 只有选中开关截图，请补交互 | 只把可见样式记为观察；明确补充键盘、异步失败和恢复；不用截图证明弹性轨迹 |
| 已有业务表格只修菜单与焦点 | 保留列、查询及 token；按命令菜单模型检查键盘与关闭，不替整页加动效 |
| 编辑抽屉保存失败后重试 | 合理初始焦点、模态边界、保留输入、防重复、错误可达、成功后合理返回焦点 |
| 快速筛选导致响应乱序 | 展示结果属于当前查询，旧响应不能覆盖；失败时条件与已显示数据的状态清楚 |
| 批量删除部分成功且连接超时 | 分辨成功、失败与未知；不重做已成功项；焦点合理且恢复动作可信 |
| 官网多个炫酷候选，移动端较慢 | 允许 React Bits，依据用途控制复杂度与活跃实例，有暂停/降级与真实验证计划 |
| 非 React 项目或其他模块未安装 | 完成普通交互；说明选用现有栈的实现，不能为动画擅自迁移全项目 |
| 复制成功、保存失败和持续断网 | 成功可 Toast；错误内联或 Alert，任何错误不进入 Toast |
| 一句话永久删除与就近低风险确认 | 前者 Modal，后者确需确认时 Popconfirm；不只按字数选型 |
| 两个简单字段与完整设置流程 | 简单字段内联/页面表单；全屏流程交独立页面，都不使用 Drawer |

## 实现后的最小操作检查

- 从区域入口仅用键盘完成关键流程。检查 Tab 顺序、实际所需的 Enter/Space/方向键、Esc 和可见焦点；不同控件遵循其语义，不给所有控件同一套快捷键。
- 打开和关闭菜单/弹窗/抽屉，包含触发器被删除、列表重排及滚动后的焦点去向；检查隐藏内容不能继续得到焦点。
- 提交正常、无效、失败与重试；必要时覆盖重复激活、超时、乱序和提交期间继续编辑。确认屏幕与状态播报对应实际结果。
- 在业务动作尚未发起的可取消阶段检查 pointercancel、Esc、移出和失焦：滑动组件包括已到末端但尚未正常释放，长按组件包括阈值前移焦/释放/Esc。取消不应新触发提交；已发起的动作按异步取消或撤销处理。仅存在取消事件处理函数不代表分支正确。
- 在目标窄屏和适用输入方式检查操作入口、滚动、浮层遮挡、触屏替代与减少动态效果；复杂效果按 [性能检查](motion-performance.md) 实测。
- 检查可访问名称、字段错误关联和状态播报；若未使用读屏器，不声称完成读屏器兼容性测试。

最终使用“规则推演通过”“源码存在该处理”“在某环境执行了这些操作”等具体措辞。记录未运行分支；不得以链接有效、代码能编译或元信息校验代替交互检查。
