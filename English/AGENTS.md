# Design Skill Cluster

Use [design-orchestrator](orchestration/design-orchestrator/SKILL.md) for interface work and load only the relevant modules. A clearly assigned local task may enter its module directly. Select skills from this edition only; both language editions share names.

For creating or modifying design skills, shared conventions, or routing, first read [FOUNDATIONS](design-system/FOUNDATIONS.md) and [ORCHESTRATION](design-system/ORCHESTRATION.md). Ordinary UI tasks need only their relevant constraints. Prefer the target product's established visual decisions and the user's current instructions.

- Use MCP metadata discovery followed by selected entry and resource reads when available; otherwise read the same files directly. Do not preload the whole cluster.
- Assign one implementation lead per region. Tokens belong to the target product and one authoritative source. Global style generates and validates them; the orchestrator consolidates results.
- Reuse existing components and behavior. Include interaction and responsive requirements during design and implementation. Missing ordinary modules can be covered directly; never claim unavailable skills were invoked.
- Use `gpt-taste` only for public marketing, never dashboards or business tools. Use `ui-ux-pro-max` for research and advice only. Inspect actual external entries before using them.
- Keep temporary style choices distinct from confirmed user preferences. Record reference evidence, adopted traits, local scope, and verification in the target project's existing module notes when continuity requires it.
- Reread files before editing. Separate parallel edit scopes and coordinate shared changes. Product-wide visual changes belong in product records; only general method changes belong in this library.
- Keep distributed skills self-contained. Use package-relative references and exclude personal paths, authoring intermediates, and unneeded raw reference dumps. Keep substantial optional guidance in on-demand references.
- Keep core and business entries concise. The original 500–2000 Chinese-character budget is an authoring guide, not an English character limit or a universal model optimum; preserve necessary behavior.
- When maintaining both editions, update English first and synchronize corresponding Chinese files without changing identifiers or behavior. If only one edition is available, record the pending translation rather than making the other edition a runtime requirement.
- Group skills by function under the language root, with internal and external packages sharing categories. Record origin and upstream attribution in README.md; preserve upstream names and notices. Do not add source-based container directories. Discover metadata before loading selected entries within categories.
- Validate metadata, resource links, actual changed behavior, and release contents. Distinguish checks performed from runtime or visual checks not performed.
