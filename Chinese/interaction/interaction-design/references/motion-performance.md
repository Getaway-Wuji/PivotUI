# 动效选型与性能

用户偏好：大多数适用动画优先直接选用 React Bits；复杂效果可用，但避免堆叠造成卡顿。以下成本分层是设计启发式，不是组件实测排行榜或设备性能保证。

## 先看用途与运行成本

| 候选特征 | 选用思路 | 必查成本 |
| --- | --- | --- |
| 局部按下、选中、淡入或短距离移动 | 普通交互的优先层，复用项目已有反馈或合适 Micro 组件 | 是否触发布局、实例数、触发频率、文本是否清晰 |
| 持续跑动、逐字动画、跟随、列表交错 | 用于能帮助理解的少量区域，完成后停止 | 节点数量、每帧工作、滚动监听、动画是否重复执行 |
| 粒子、流体、着色器、WebGL、3D/物理 | 为明确的视觉重点单独评估，在其区域内使用 | 画布数量、像素比、分辨率、粒子量、材质/模型/纹理、GPU 与 CPU 消耗 |

复杂度不能只看外观或依赖名。小范围着色器可能轻于大量 DOM；单个简单组件复制数百次也可能昂贵。最终以选中源码、实际数据量和目标设备运行结果判断。

普通业务页先用事件触发、短时运行的反馈。高表现力页面可把一个重点区域作为复杂效果的起点，再依据性能结果决定是否增加；这是本模块的审慎起步策略，不是强制“每页只能一个”的规则。不能在每一行、每个按钮和每张卡上同时启用粒子、跟随或长期循环。

## 给选中效果明确生命期

每个持续效果记录：可见区域、何时启动、何时暂停、何时释放、静态替代、目标设备。建议在组件交接中用一行说明即可。

- 首屏关键操作先可用；重型效果按需加载。已有页面不要为局部动画新建第二套动画引擎，先检查现有依赖和组件变体。
- 离屏时暂停需要连续计算的效果，页面隐藏时停止无必要工作。仅用 CSS 隐藏或 `opacity: 0` 不代表循环已停；确认 requestAnimationFrame、计时器、WebGL 与物理循环的实际启停路径。
- 卸载、路由离开或重新初始化时清理监听、观察器和循环，释放适用的图形资源。共享资源按所有权释放，避免误删其他实例仍在使用的资源。
- 按实际组件支持调低渲染像素比、粒子数、帧更新频率或纹理大小。不要凭名字编造 props；不支持暂停或降级时在外层控制挂载、修改已接入源码或选择其他候选。
- 大列表中的动画需要限制同时参与的行；保持稳定 key，筛选后不重复播放整页入场。虚拟化若已有则配合，不为普通小列表强行新增架构。

## 输入方式与减少动态效果

- `prefers-reduced-motion` 下保留信息与任务完成路径，去掉大幅位移、视差、抖动、连续粒子与非必要循环；可用即时切换、轻淡入或静态画面。CSS 降级不会自动停掉 JavaScript/Canvas 循环，按源码验证。
- hover 能力和精细指针用于增强，不是核心入口条件。触屏提供点击、按钮或可见说明；拖动流程提供可操作的替代。避免全局拦截滚动或占用浏览器手势。
- 连续轮播/滚动展示按使用需求提供暂停控制，键盘进入或用户交互时停止抢占阅读；减少动态效果时优先静态内容。关键文字不能长期被打乱、模糊或隐藏。
- 反馈动画不能延迟用户继续操作或承担唯一状态语义。状态先可靠更新，动画响应状态；被打断、反向触发或关闭时仍保持正确业务状态。

实现依据可查：[MDN 减少动态效果](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)、[页面可见性](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)、[Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)。

## 实际界面的验证

1. 在目标内容规模下比较禁用效果的基线与启用效果的版本，覆盖滚动、连续输入、开关浮层和快速重复操作。
2. 观察明显掉帧、长任务、输入响应和路由离开后的资源是否仍增长；记录浏览器、设备或模拟限制及测试范围。视口变窄不等同于低端手机实测，不能据此保证真机流畅。
3. 隐藏/切回页面、滚出/滚入区域、卸载/重挂载后检查循环与状态；验证减少动态效果与触屏替代。
4. 出现阻塞时先减活跃实例、降低质量、暂停离屏工作，再替换过重方案。保留可用的静态或轻量路径。

仅制作 skill 或审阅截图时记录这些是实施要求，不能声称已完成性能测量，也不给无依据的“稳定 60fps”承诺。
