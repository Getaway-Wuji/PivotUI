# 按钮交互

这是 `interaction-design` 的按需子模块。继承 [根入口](../../SKILL.md) 已确定的任务范围、token、证据标记和组件约定；由根入口路由进来时不重复读取它。直接进入且缺少约定时，只补读其“接受范围与现有决定”；目标项目规范仍是可选上下文。

负责触发命令的按钮及其反馈。导航跳转交给 [导航交互](../navigation-interaction/SKILL.md)，表单整体校验交给 [表单交互](../form-interaction/SKILL.md)，确认与结果容器按 [浮层组件](../floating-components/SKILL.md) 选型。以下为实现规则，不是从静态参考观察到的行为。

## 选择适用状态

先确定动作是即时本地操作、远程变更还是打开界面。hover/focus/pressed 属于输入反馈；selected/checked 是持久选择；pending/error 是业务生命周期。它们可能同时存在，不能只用一个 `active` 表示。

| 触发条件 | 状态变化 | 用户反馈 | 退出或恢复 |
| --- | --- | --- | --- |
| 可操作按钮被指针指向或键盘聚焦 | hover / focus-visible | 沿用项目底色、边框或焦点环；必要时轻量动效 | 移出或失焦清理临时外观，持久选择不变 |
| 用户完成有效激活 | pressed 后执行实际命令 | 可选轻压感、涟漪；按钮名称始终可理解 | 释放后复原；业务动作未发起的取消不能触发提交 |
| 提交有效远程操作 | idle → pending | 原位“保存中”等反馈，尺寸稳定 | 防重复；真实结果决定 confirmed / error / outcome-unknown |
| 当前条件不可执行 | enabled → disabled | 原因可找到，必要条件可行动 | 条件满足后恢复；不把唯一解释藏在不可聚焦控件的 hover 中 |
| 收到成功确认或明确失败 | pending → result | 成功按任务轻量反馈；失败就近持续呈现或用 Alert | 保留上下文；修正或安全重试，不用 Toast 呈现错误 |

即时动作不人为加载，不为每次成功弹窗。危险程度与确认方式来自业务影响，不能仅凭红色按钮决定；低风险简单确认不使用 Modal，高风险确认不使用 Popconfirm。不可逆操作即使文案简短也按浮层模块使用 Modal。

## 语义与输入

- 用原生 button 执行命令，设置合适的 `type`，避免非提交按钮意外提交表单。保留 Enter、Space 的原生激活，不额外重复触发；纯图标按钮具有可访问名称。
- 原生 `disabled` 会改变可聚焦性。使用 `aria-disabled` 保留可发现性时，需在实际执行函数阻止鼠标、键盘和程序触发；视觉变灰不足以禁用。
- pending 期间按钮与执行函数共同防重复；不移除当前焦点而不安排去处。已有内容继续可读，无关操作不必冻结。请求身份、幂等与结果未知见 [异步与恢复](../../references/async-recovery.md)。
- 多选/切换按钮仅在确有按下选择语义时使用 `aria-pressed`；普通执行按钮不因点击留下“已选”。表单开关、复选框和单选控件由表单模块处理。
- 动画包装不嵌套可交互元素，不吞掉链接、按钮或键盘事件。磁吸保持稳定命中区，装饰火花不等于操作成功。

## 动效与特殊手势

需要动效时按 [React Bits 接入](../../references/react-bits.md) 选匹配组件，并继承 [性能约束](../../references/motion-performance.md)。普通按钮优先局部、短时反馈；复杂效果不复制到每一行或每个入口。

长按/滑动确认只在该手势适合任务时采用，并提供无需持续按住或拖动的等价方式。验证业务动作发起前的释放、pointercancel、Esc、移焦；达到阈值已经发起的动作按真实取消或撤销能力处理，不倒放动画伪装取消。React Bits 的 Hold Button、Slide Commit 已知取消缺口见接入指南，使用前补齐。

## 交付检查

- 键盘完成激活，焦点可见；禁用与 pending 不能被其他事件路径绕过。
- 快速重复激活只产生约定的业务执行；成功、失败、超时均有明确且真实的反馈。
- loading 切换不引起命中区跳动或焦点丢失；失败后仍能继续。
- 悬停、触屏与减少动态效果均保留同一动作结果。只有实际运行后才报告运行通过。
