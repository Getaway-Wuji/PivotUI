# 表单与设置页流程设计

组织整页新建、编辑与配置流程，让用户清楚当前正在修改什么、不丢失有效输入，并明确改动何时生效。负责页面级表单结构、分区导航、保存/取消流程与保存后路由；底层字段/输入法/异步竞态由 `form-interaction` 补充，共享输入控件由 `component-system` 提供。

## 建立工作约定

从需求与目标项目中确认：流程类型（新建、编辑已有记录、系统设置或分步向导）、字段分组与联动依赖、必填与可选规则、保存模式（统一提交、分卡片保存或自动保存）、权限与只读约束，以及保存/取消后的去向。常规细节基于合理假设推进，仅在业务规则缺失且影响流程结构或数据安全时提问。

## 先选流程形态，再定布局

| 业务特征 | 推荐结构 | 关键保障 |
| --- | --- | --- |
| 4–12 个相关字段（新建/编辑实体） | 单栏或清晰两栏分区页 + 顶部/底部操作栏 | 保持单一阅读顺序，输入框宽度与预期内容长度匹配 |
| 大型产品/账号设置（15+ 配置项跨多个领域） | 左侧目录/Tabs + 独立作用域配置卡片（或吸底脏状态保存栏） | 明确告知是分卡片即时保存还是整页统一保存 |
| 存在先后依赖的流程（开通、配置向导、审批提报） | 清晰步骤条 + 上一步/下一步 + 提交前核对 | 返回上一步保留已填数据，校验失败不清空前序步骤 |

## 核心流程规则

1. **草稿与已提交数据严格隔离**：在独立草稿副本上编辑，确保点击取消绝不污染原记录，保存失败绝不清空用户输入。
2. **明确未保存状态与操作范围**：存在未保存改动时给出清晰提示，离开或取消有改动表单前确认；提交期间禁用重复提交。
3. **长表单采用“行内错误 + 顶部汇总”双定位**：字段错误就近绑定（`aria-describedby`）；跨分区表单提交失败时通过 `Alert` 汇总错误并提供跳转定位，将焦点移至首个错误字段或汇总区。
4. **守住上下文与返回路径**：保存或取消后保持与来源详情页/列表页的返回连续性（配合 `detail-page-design`、`data-list-design` 与 `app-shell-design`）。全屏或复杂编辑使用独立页面，不强塞进 `Drawer`（遵循 `floating-components` 边界）。
5. **覆盖加载与并发异常**：妥善处理初始数据加载失败、只读/锁定字段、后端返回字段级错误，以及保存超时/结果未知时的重试与恢复。

## 整合与验证

复用产品既有应用框架、权威 Token 与组件库控件。复杂字段校验、输入法组合态或异步竞态交由 `form-interaction` 补充；窄屏吸底操作栏与触控输入交由 `responsive-design` 适配。

交付所请求的设计规格或可运行页面，说明流程结构、保存/取消模型、已验证的草稿保护与失败恢复路径，以及未覆盖的运行检查范围。包范围见[包说明](PACKAGE.md)。
