# 组件接口约定与复用决策

扩展接口、新增变体或将组件提升为公共能力时读取。这里描述应通过项目现有框架表达的设计决定，不要求新建一套固定 props 结构。

## 选择复用层级

| 目标项目中的证据 | 处理方式 | 保留或建立的约定 |
| --- | --- | --- |
| 已有组件覆盖任务 | 直接使用 | 导入、主题、事件含义、键盘行为和表单绑定 |
| 已有尺寸、变体、主题槽位或组合方式可以覆盖 | 配置已有能力 | 使用受支持的 API，不通过深层选择器依赖未公开的内部结构 |
| 多个调用方需要相同且稳定的组合或组件库适配 | 组合公共部分或建立薄适配层 | 一份实现、明确输入/事件、可访问名称及焦点/ref 访问 |
| 缺少任务必需的语义或行为能力 | 在合适基础组件上补齐 | 明确归属、适用状态、设备行为、示例与检查 |
| 布局仅属于一个页面，或容易随内容改变 | 保留在局部 | 由页面负责；以后形成稳定的可复用约定再提取 |

引入封装前先看附近调用方。封装应落实真实产品规则、适配不兼容接口或组合重复行为；只将上游所有 prop 改名，会增加另一套维护成本。使用复制源码式组件时，保留一份由项目维护的实现并记录来源，不在不同页面散落各自修改的副本。

## 按需要描述接口约定

对受影响组件记录：

- **用途与组成结构：**服务的任务、必需及可选部分，以及哪部分负责可访问名称、值、动作或内容分组。
- **输入与归属：**值类型、稳定标识、初始值、支持时的受控/非受控模式，以及请求与校验的负责人。避免同一个值由两个竞争存储维护；组件生命周期内不悄悄切换控制模式。
- **事件：**触发条件、载荷、时机和真实依据。选择变化、请求提交、操作完成、动画结束是不同事件。保留已安装组件库的事件语义。
- **组合：**支持的内容插槽、原生属性、可访问描述、焦点/ref API 和样式扩展点。暴露调用方真正需要的能力，不把私有 DOM 结构变成公共接口。
- **变体与状态：**用途、默认值、支持组合、状态优先级，以及各变体间保持不变的部分。
- **调用方与变更范围：**公共导入位置、现有调用方、整合负责人，以及接口变化时的迁移需要。

通用 Select、Table 基础组件接收数据与回调；项目请求、权限、导航和业务校验属于页面或名称清楚的领域封装。保留项目已有表单控制器，不在 Field 内建立第二份值存储。

## 分清变体维度

| 维度 | 表达的决定 | 合理用途示例 |
| --- | --- | --- |
| 意图/角色 | 动作或状态的含义 | 危险操作与普通操作 |
| 强调/外观 | 相对周围内容的优先级 | 主操作与低强调工具操作 |
| 尺寸 | 适应内容与设备的比例 | 工具栏控件与突出展示的行动入口 |
| 密度 | 重复区域内的空间量 | 紧凑桌面数据表格与舒适设置表单 |
| 组合结构 | 信息或控件结构的差异 | 分裂式操作；带次级说明文字的按钮 |
| 运行状态 | 此刻发生什么 | Pending、selected、invalid、disabled，不是永久样式变体 |

沿用项目命名。不同库中的 `small`、`sm`、`mini`、`default` 不是可互换 API 值；只有需要时才在适配边界映射概念。某个库的 `type` 可能指外观，另一个库中则指原生提交行为，须明确保留两种含义。不引入 `small && large` 等布尔组合，也不建立 `blueRoundSavingButton` 这样的变体。

明确适用状态组合：pending 可以保留标签并阻止再次执行；selected 可以与焦点并存；invalid 字段可能已有非空内容；readonly 不等于 disabled。禁用状态无需虚构悬停行为。业务不可用、缺少权限、操作进行中可能需要不同解释。提交按钮是否为触发校验而保持可用，遵循已约定的交互模型。

## 将尺寸视为一组关系

尺寸方案联动行高、块向内边距、边框、图标框、行内间距与视觉对齐。可用的内容关系是：

`control block size >= max(text line box, icon box) + block padding + borders`

实际最小值遵循产品主题与输入设备约束。多行内容可以增高，固定高度不能裁切翻译文本或放大后的文字。命中区域可以超出视觉形状，但不能与相邻目标重叠。不通过缩减焦点提示或可操作性获得紧凑效果。

相邻控件按可见基线与控件框配套。紧凑表格内嵌 Button、Select 时，选择兼容的已有尺寸，或建立有依据的局部映射；不要分别随意缩小行高、字段高度和图标。改变纵向密度时，仍保留合适横向内边距与可读标签。项目支持双向文字时使用逻辑间距属性。

## 三个小型接口示例

以下是说明性规格，不是可执行组件代码，也不要求沿用示例名称。

| 示例 | 稳定接口约定 | 有意保留的差异 | 业务负责人 |
| --- | --- | --- | --- |
| 订单列表与设置共用的操作按钮 | 已有 `Button` 导入；原生动作语义；当前 click/press 事件；pending 绑定真实操作；保留可访问名称 | 按场景使用已有尺寸/强调；仅危险操作使用危险意图 | 调用方执行操作并反馈结果 |
| 筛选选择器 | 稳定选项 ID 与标签分开；value/change 约定；明确清空值；若控制展开则独立维护 | 单选/多选、本地/远程搜索是明确能力，不是装饰皮肤 | 页面负责查询、选项及响应顺序 |
| 两个列表共用的实体表格 | 稳定行标识；列定义及单元格渲染；排序/分页/选择归属明确；空白/加载/错误插槽 | 已有密度；有作用域的列显隐或溢出策略 | 页面提供领域列、请求和行操作 |

新增紧凑变体时，记录需求（如桌面数据工具栏中的重复控件）、已有尺寸是否足够、映射 token、受影响部分、适用场景与检查。单页临时内边距调整不自动成为新的公共 token。修改公共 API 时检查调用方，必要时提供迁移或兼容适配，并同步更新示例。
