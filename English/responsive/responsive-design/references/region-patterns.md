# Adapt regions while preserving the task

Read only the relevant rows. These are supplemental design methods; no supplied image demonstrates these product states. Decide each region's actual priority with its page owner.

| Region / change condition | Retain | Rearrangement and continued operation |
| --- | --- | --- |
| Navigation labels/actions no longer fit | Current location, destinations, essential account/task actions | Collapse into an explicitly named navigation control or reuse the shell's existing variant. Keep destinations, current-page indication, open/close state, and keyboard access. When resizing an open navigation panel into desktop navigation, reconcile visibility, scroll lock and focus; do not strand focus in a hidden panel. Narrow width alone does not select Drawer. |
| Hero / main-and-aside columns cannot support readable content | Main proposition/task, primary action, relevant supporting information | Stack in a meaningful source order. Reposition supplementary material after the related main section. Crop images only if their meaning remains intact; use responsive sources when available. No required viewport-height hero or universal column ratio. |
| Control row, filters, or form becomes cramped | Labels, current values, validation, submit/cancel paths | Wrap or stack groups; make long labels fit without removing names. Filters may move to a panel with active-filter feedback and a clear apply/reset flow. Preserve draft values and validation across changes. A full-width button is a task-specific variant, not a rule for every narrow layout. |
| Comparison table exceeds usable space | Row identity, column meanings, comparison fields, sort/filter state, row/bulk operations | Keep a semantic table with a bounded horizontal scroll region when comparing columns matters. Priority columns plus a named detail disclosure are valid if omitted fields remain accessible. Cards are an alternative for record-by-record work, not an automatic mobile conversion. Keep selection, all-record vs page scope, totals, pagination, and bulk-operation feedback clear. |
| Chart labels, marks, or legend compete for space | Units, period, series identity, essential comparisons, access to values | Change chart arrangement, label placement or tick frequency before shrinking all text. Keep removed tick values/data available via an accessible summary/table or detail control. If changing aggregation, explain it and preserve access to the original resolution needed for the task. Re-measure the chart container on resize. Touch and keyboard users need a route to hover-only values and legend controls. |
| Modal no longer fits usable width or height | Purpose/title, entered data, errors, close/cancel and primary action | Use a fitting width and bounded content scroll. A full-screen or sheet presentation is possible only when appropriate to the Modal's task and existing interaction contract; retain its use conditions and confirmation rules. Keep actions reachable at short height and with the keyboard open, and preserve dialog semantics and focus entry/containment/return. Width changes do not justify changing destructive-action behavior. |
| Contextual editing Drawer no longer fits usable width or height | Editing context, draft, errors, save/cancel and return path | Adjust width and bounded content scrolling while retaining the Drawer use conditions and modality. Do not convert it to a full-screen Drawer or use Drawer for a simple form. If the task cannot fit, coordinate a separate editing page or inline area with the page owner, preserving draft, pending outcome tracking and a sensible return/focus path. |
| Sticky/fixed header, sidebar or bottom action overlaps content | Context and action access, visible focused item | Account for actual occupied space and safe areas. Reserve content space when fixed, or release sticking when height is inadequate. Avoid multiple competing scrollers. Check anchor targets, last rows, expanded errors and the final form action under overlays. |
| Long text, URL, code or wide media crosses boundaries | Complete meaning, identifiers and copy/open actions | Wrap ordinary text; allow sensible breaks for URLs. Use bounded scroll for code or inherently two-dimensional content. Truncation requires a discoverable way to read the full value on keyboard and touch; a `title` attribute alone is insufficient. |

Tables and charts do not give the surrounding page a blanket exemption from reflow. Keep toolbars, titles, notes, and pagination usable outside the local scroll area. A sticky identity column must leave enough room to inspect the remaining fields; disable it when it consumes the useful viewport.

Separate business priority from decorative priority. A low-contrast appearance does not establish that a field is expendable. Hide decorative duplicates when useful, but document the access path for any information moved out of the immediate view. Do not equate a visually clean screenshot with a complete workflow.

Reuse existing component contracts and behavior. If a new compact, stacked, or disclosure variant is needed, hand its trigger, semantics, state continuity, and affected callers to the component owner. One named implementer reconciles the result.
