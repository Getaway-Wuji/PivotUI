# 项目设计约定与交接

在需要确定全局样式、协调多个区域、处理外源冲突或跨窗口接续时使用。复用目标项目已有记录方式；局部修复只需保留关键决定，无需另建完整文档体系。

## 本次工作约定

在执行前用足够简短的记录明确以下内容，已知内容直接填入，不要求用户逐项回答：

| 项目 | 需要确定的内容 |
| --- | --- |
| 目标与范围 | 页面或区域、使用者任务、设计说明还是实际界面、允许修改的范围 |
| 参考用途 | 忠实还原、借鉴局部、沿用既有品牌或探索新方向 |
| 分工 | 每个区域的主力、辅助者的具体贡献；没有对应 skill 时由当前执行者完成的内容 |
| 设计来源 | token 或主题的实际位置、既有组件、已定风格及暂定选择 |
| 行为与设备 | 必要状态、主要操作、目标设备和动效范围 |
| 交付检查 | 产物位置与当前任务需要验证的结果 |

实际读取的 skill 名称和入口可以记录在当前工作环境中，但可移植的项目文档使用项目相对路径或 skill 名称，不把机器上的个人安装路径写入分发内容。

持续任务可简记选定的规范入口、分配的贡献、已读共享规则／资源及可用的 revision、尚未覆盖的能力缺口。复用当前上下文，不为每个小修复新增跟踪文件；回链不启动第二轮流程。上下文重置或来源改变后，重新打开实际需要的规则，不凭过期的“已加载”标记跳过。

## 把案例证据交给产品

涉及具名参考或案例研究时，只补会影响决定的信息：案例 ID 和来源版本、真实页面／界面范围、借用特征、保留的产品规则、证据类型及相关未知项。建议与合成演示需和观察结果区分。说明负责人采用了什么、哪些仍为暂定，以及哪些行为仍需实现或验证。纯咨询停在建议。

用户要求项目设计文档时，将这些决定适配进已有记录或 `DESIGN.md`：用途和区域、选定视觉关系、组件约定、来源链接，以及补充的交互／响应式决定。链接真实可编辑的 Token 源，或从它派生文档中的值，不另行维护独立 Token 表。保留当前品牌，除非用户要求改变。准备此文档不调用 Stitch，也不证明界面已渲染。

## Token 的归并

1. 先定位项目现有样式来源：主题文件、CSS 变量或组件库配置。存在多层生成关系时，确认哪个是可编辑源、哪些是生成结果。
2. 新项目先确定设计方向，再落实当前任务需要的颜色、字体、间距、尺寸与形状；不为了填表先发明完整品牌。
3. 外源生成的体系可完整采用、映射到已有主题或以项目配置替代。保留一处可维护的权威来源，避免两套配置独立变化。
4. 新增值优先检查既有语义与变体。营销大标题、紧凑表格、危险按钮等差异通过命名明确的区域或组件变体表达。
5. 全局变更先判断影响范围，再更新来源及受影响的组件。辅助者提出建议，主控归并；不让不同文件用同名全局变量表达矛盾值。

已有紫色品牌与某个外源“禁用紫色”的默认规则冲突时，保留用户品牌要求，查找实际支持的适配方式；无法兼容则局部借鉴或更换主力。不能仅在末尾覆盖颜色后就声称通过了该外源完整检查。

规范检查以用户选定的设计目标为准。精确还原图中的视觉与现有品牌不同，可以是明确的新目标；需要保留业务品牌时，先确定参考仅用于哪一部分。

## 组件 交互 响应式的接续

- 布局前：盘点公共组件，明确主要内容与操作在窄屏上的优先级；交互复杂时先确定状态及转换。
- 实现中：页面主力组织内容，组件负责人落实复用和必要变体；其他能力处理分配的行为与设备问题。
- 完成后：检查实际页面与主要流程。已有主力覆盖的行为直接复用，辅助者只检查或修正缺口。

公共 token、组件接口与全局样式由明确负责人整合。相互独立的区域可以分工；对同一组件的反馈集中处理，避免多个执行者同时重写。

## 框架与页面返回职责

框架与页面组合时，框架提供路由身份、标题／操作插槽和真实滚动容器；页面负责查询、选择、草稿及结果有效性。复用产品状态机制，并明确一个返回协调者。恢复正确的路由实例，处理数据／权限变化，再统一恢复有效的页面／局部位置及稳定记录焦点。页面不能假定 `window` 就是框架滚动容器；导航和页面各自的副作用不能争抢焦点恢复。只针对具体缺口读取相关模块方法。

## 保存与接续

多页面或多窗口工作，优先更新已有设计记录。没有记录而确有接续需要时，可在目标项目建立 `design-system/PROJECT.md`，保存当前采用的方向、token 来源、区域分工和未完成项；这是可选约定，不是 skill 的运行依赖。

记录应描述当前有效状态：

- 已采用的品牌与组件规则，以及仍暂定的选择。
- 各区域的主力、参考采用范围和实际成果位置。
- 相关文件与可再次访问的参考；聊天附件不可假设在其他窗口可见。
- 已完成的检查、实际未验证的部分与下一步需要处理的事项。

使用项目相对路径，不复制各个 skill 的完整指令，也不把某个客户项目的 token 写回本技能库当作所有项目的默认值。

重新接续前读取最新文件；已有成果有效时从未完成处继续。只有用户需求、可用能力或实际发现变化时才调整既定路由。
