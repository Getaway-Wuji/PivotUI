# 应用外壳设计

让不同页面保持同一应用的连续体验：用户能确定当前位置、进入其他任务，并在返回时找回原来的位置。负责页面内容周围的框架，包括信息架构、侧栏／顶部导航、面包屑、页面标题与操作区、宽度、固定区域及滚动归属。

## 从现有产品开始

检查现有路由与布局、导航及权限规则、共享组件、权威 Token 来源、目标屏幕和任务范围。保留已可用的结构。新增参考本身不构成更换路由器或另建主题的理由。

区分**持续存在的框架**（全局导航与控件）、**路由上下文**（面包屑、标题、页面操作）和**页面内容**。先映射有代表性的列表 → 详情 → 编辑路由，再决定空间布局。同一个导航项可以代表这三类路由；它们的标题和面包屑末端各不相同。

## 选择并定义外壳

新建后台外壳并采用所给参考时，使用 Ant Design Pro 方向：固定且可折叠的左侧栏、承载全局控件的顶部 Header、位于页面内容上方或 Header 内的面包屑，以及独立滚动的右侧内容区。保留这套可辨认的组合，同时适配目标产品。这是参考模式，不要求所有任务都采用，也不表示所有 Ant Design Pro 配置完全一致。

新建或大幅调整框架，或有未解决的路由、滚动或返回状态问题时，读取[框架决策](references/frame-decisions.md)的相关章节。一并确定：

- 哪些部分跨页面持续存在，哪些来自当前路由？
- 哪些区域共用内容起始线与宽度，边界应在哪里？
- 每个滚动轴由哪个元素负责，哪些元素持续可见？
- 可用空间变化时，导航、焦点和返回状态如何延续？

当任务需要其他结构时，不强制侧栏、页面 Tab 系统、固定页面标题或统一宽度。核对来源归属或框架配置时，读取[参考范围](references/reference-scope.md)。区分用户陈述、已核实事实、估计与补充设计。

## 明确归属后实现

主控选择本模块作为外壳负责人。Dashboard、列表、详情和表单负责人组织各自内容。约定路由元数据、标题／操作插槽、内容宽度与内边距、滚动容器和返回状态的责任，避免重复页头或嵌套滚动容器。

`navigation-interaction` 补具体导航与焦点缺口，`component-system` 提供共享基础组件，`responsive-design` 补导航收纳或跨屏缺口。每个区域／组件由一个明确的实现者整合。复用已满足要求的行为；缺少专家模块时，直接补齐普通缺口。沿用产品 Token；`global-style-skill` 处理真实主题缺口，主控归并变更。独立使用所需的基础规则见[共用约定](references/foundations.md)。

交付用户要求的实现或规格。在内容变化时保持框架稳定；依据产品的导航约定保留筛选、草稿、选择、滚动与焦点，并为直接进入或记录已移除的情况提供可靠回退。

## 验证与交接

使用[验证](references/verification.md)中的适用检查。覆盖长标签、多层路由、返回路径、键盘使用、展开收起、窄屏与短视口、固定区域遮挡和实际渲染文字对比度。静态规格不能证明运行时成功。

交回选定框架及其适用条件、路由／内容约定、复用的组件与 Token、来源依据与补充决定、产物及实际执行的检查。将需要延续的决定记入目标项目已有记录；本制作仓库不是运行依赖。
