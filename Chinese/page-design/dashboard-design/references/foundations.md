# Dashboard 共用设计约定

来源：《界面共用设计规范》**0.2，2026-11-14** 的 Dashboard 摘编。

本文件随 skill 独立使用，只保留设计执行需要的共用约定。目标项目已有的设计规范、组件和用户明确要求优先；不要求建立特定目录、调用其他 skill 或访问原始参考图片。

## 继承目标产品的设计体系

- 开始时识别目标产品已确定的主题、品牌色、字体、密度、页面框架与组件；在本次任务范围内继承。
- 产品尚未确定的视觉值可提出本次方案，但标明是建议，不能写成用户已确认的偏好。
- 不同产品可以采用不同视觉体系；同一产品中相同语义、组件和操作保持一致。
- 颜色、间距、圆角、阴影等公共值沿用目标项目的一处可维护权威来源，避免为 Dashboard 单独建立重复体系；有主控分工时，由其归并公共变化。
- 同一产品确需紧凑、宽松或不同主题的表现时，定义有用途的变体，而不是让每张卡自行取值。
- 局部参考默认只作用于当前区块。全产品变化须符合用户明确要求，并在目标产品中说明影响范围。

## 明确 Dashboard 的负责范围

- 围绕使用者要理解、判断和执行的任务安排仪表盘内容；面积、位置与强调程度反映业务重要性。
- 负责指标优先级、图表选择、概览布局和数据解释；沿用已有导航、标题区、内容起点与滚动框架。
- 概览可以包含摘要表、筛选和详情入口，但不因此扩大为全站表单、列表或导航重设计。
- 各模块共用按钮、输入框、标签、弹层等基础组件；新增变体应有实际任务理由。

## 保持可阅读的视觉关系

- 先用位置、尺寸、字重、间距和分组建立层级，再用颜色与装饰补充。
- 容器边界应表达独立内容、操作或状态；避免仅为装饰连续套叠。
- 字体层级数量有限且用途明确。中文、数字与单位协调，长名称与实际数据量不破坏布局。
- 页面背景、内容表面、文字、边界、交互强调、业务状态与图表系列各有语义，不能互相混用。
- 相同指标跨图尽量保持颜色编码；状态同时提供文字、图标或其他线索。
- 文字、边界、选中与焦点应在实际背景上清楚可辨，尤其检查浅色辅助文字和深色表面。
- 图标保持一致的视觉语言；难以识别的操作提供可理解的名称。

## 使用参考时保留判断

- 提取参考中的结构、主次和可复用关系，再替换为实际业务内容，不机械保留卡片数量或示例品牌。
- 多份参考各自承担明确用途，并统一为一套字体、表面、边界和控件表达。
- 区分可见事实、提示词要求和自行补充的方案。静态图不能证明键盘、加载、窄屏或动画已经实现。
- 未能从源文件核实的色值、字号与尺寸应写为估计或实施建议；不把图像观察表述为精确测量。
- 业务界面的动效用于反馈与状态转换；表达强度随任务、使用频率和动态偏好调整。

## 按任务继续读取

- 指标口径、图表前提、密度与不同屏幕的排列：读 [data-and-layout.md](data-and-layout.md)。
- 导航适配、展开、重排、更新和操作状态：读 [interaction-patterns.md](interaction-patterns.md)。
- 仅制定规范时检查规则与引用；实现页面时再验证实际显示和主要操作，按真实完成情况说明结果。
