# 指标、图表与布局工作方法

本文件是结合 S26–S37 等参考整理后补充的方法，不代表原截图已实现这些行为。先用 [selection-guide.md](selection-guide.md) 确定 A–G 主结构，再用本文件核对数据和版面；视觉主题见 [visual-recipes.md](visual-recipes.md)。项目现有规范与组件优先，以下选择不构成用户的全局视觉偏好。

## 1. 先定义指标，再画卡片

每项主要指标至少明确下表内容；可放在口径说明或详情中，不必全部挤进卡片正文。

| 项目 | 要写清什么 | 对设计的影响 |
| --- | --- | --- |
| 名称与问题 | 指标回答的业务问题 | 决定标题、首屏位置与是否需要展示 |
| 值与单位 | 金额币种、数量、时长、容量或比例 | 单位跟随数值；不同币种不得无换算直接合计 |
| 计算口径 | 求和/去重/平均/中位数；比例的分子与分母 | 相同名字不能隐藏不同口径 |
| 范围与时间 | 对象、组织、地区、人群、时区、起止时间 | 与筛选状态及图表范围一致 |
| 比较基准 | 上期、去年同期、预算或目标 | 在变化值旁写明比较对象 |
| 业务方向 | 越高越好、越低越好、合理区间或仅描述 | 决定状态语义，不由正负号直接决定 |
| 更新与来源 | 数据源、最近成功更新时间、预计延迟 | 决定新鲜度提示与是否允许给出结论 |
| 后续动作 | 查看口径、分组、明细或处理对象 | 只有真实目的地存在才把卡片做成可点击 |

- 比例同时考虑分母与样本量：`10/20` 与 `1,000/2,000` 都是 50%，判断可靠性和影响范围不同。
- 平均值要说明按记录、用户、天数还是其他对象加权；不能把各组百分比直接平均成总体转化率。
- 同比是相对去年对应周期；环比是相对前一个可比周期。卡片写“较上月”，比只写“↑12%”更明确。
- 使用变化率时，通常按 `(当前值−基准值)/基准值` 计算；基准为零或负数时不能机械套算并展示误导百分比，改给绝对变化与说明，或采用业务已定义的方法。
- 百分比从 20% 到 25% 是增加 5 个百分点，相对增长为 25%；标签应区分 `%` 与“百分点”。
- 时间未结束时标“截至当前”；与完整上期相比需说明，或比较上期相同已过时间，避免伪造增长。
- 退款率、错误率、延迟等负向指标下降可能是改善；收入下降通常是恶化。方向未知时用中性描述，不自动标红绿。
- 目标、阈值、异常级别与业务结论须有数据或业务规则来源；没有目标就不画完成率，没有依据就不写“异常”。

### 选择首屏指标

从用户的决策反推指标：先选用于判断结果的指标，再选能解释变化或提示代价的指标。例如收入增长可以同时看毛利或退款，避免单一总量掩盖问题；仅在这些数据与角色任务相关时加入。辅助指标放到解释区，重复描述同一事实的指标合并。指标数量由决策价值和可读空间决定，不固定四张卡。

卡片按实际需要组织“名称＋数值/单位＋时期＋比较说明/状态”；口径、来源和更新详情可进入说明。目标、变化率、小趋势和操作按钮都是条件项。没有历史只展示当前值，没有分母不补造百分比。

## 2. 区分数据状态

| 状态 | 表达与动作 |
| --- | --- |
| 已知为零 | 显示 `0` 和单位；零值参与相应计算 |
| 值缺失/不适用 | 显示 `—` 并说明缺失或不适用；不要按零计算 |
| 首次没有数据 | 说明产生数据的条件，提供已有的接入或创建入口 |
| 筛选无结果 | 保留当前筛选，允许清空或放宽条件 |
| 加载中 | 保持版面尺寸，显示加载反馈；不要用假数字计数制造变化 |
| 加载失败 | 保留可用上下文，说明失败区域并给重试 |
| 部分成功 | 成功部分正常展示，失败部分单独说明；不把全页显示成成功更新 |
| 数据过期/连接中断 | 显示最近成功更新时间和状态；缓存数据标为上次结果 |
| 无权限 | 说明该区域不可查看，避免通过汇总、提示或导出泄露受限数据 |

图表缺失点用断线或缺失标记表达，不自动补零；预测、估算和插值与实测数据明确区分。参考用例中的数字仅能作为已标注的示例数据。

先区分交付方式：真实数据界面按实际来源显示；概念稿/原型可以使用标明为演示的自洽数据，保留指标定义与未来接入条件。业务需要但未接入的核心模块展示“待接入/待配置”；无业务依据的可选分析才省略。纯视觉示例不能作为已上线数据能力的证明。

## 3. 从业务问题选择图表

| 要回答的问题 | 优先表达 | 数据前提与边界 |
| --- | --- | --- |
| 随时间怎样变化 | 折线；需要强调量级时用轻面积 | 时间粒度一致；保留真实峰值与缺失段 |
| 哪些对象更高/更低 | 排序横条或点图 | 对象名称长时横条更易读；需精确读数时附数值 |
| 当前与基准差多少 | 分组条、点图、差值条或参考线 | 单位、口径、时间范围可比 |
| 总量由什么组成 | 堆叠条；少量类别可环图 | 类别互斥且覆盖同一总体；不是所有比例都能相加 |
| 各组占比怎样变化 | 百分比堆叠条 | 同时给样本量/总量，避免隐藏规模差异 |
| 数值分布如何 | 直方图、箱形图或分位数摘要 | 有足够个体数据；标清分箱或分位含义 |
| 范围或不确定性怎样变化 | 区间柱、范围带或误差线 | 有实际上下限，标明最小最大值、预测范围或统计区间；不同含义不能混用 |
| 两个量是否共同变化 | 散点图 | 同一对象成对数据；相关不等于因果 |
| 用户在哪一步流失 | 漏斗或逐步转化横条 | 有固定有序步骤、去重口径和转化时间窗 |
| 用户/资源流向哪里 | 桑基或路径图 | 有节点、连接、流量；分支关系是实际问题 |
| 距目标有多远 | 目标条、子弹图、数值加目标线 | 有真实目标、周期和同口径实际值 |
| 不同批次如何变化 | Cohort 热图 | 分组加入时间与相对观察周期明确 |
| 空间位置有什么影响 | 地图加对象明细 | 位置、距离、线路、覆盖或区域模式影响判断 |
| 现在要处理哪条记录 | 有排序和状态的队列/表格 | 列表本身就是最佳表达，不必再加图表 |

- 趋势小图只表达方向，主趋势图还需时间、单位和基准。不能用同样的装饰曲线复用到所有 KPI。
- 柱/条的长度用于比较大小时，数值轴从零开始；确需强调小差异可改点图或差值图，并清楚标示范围。
- 同一数轴保持同一单位和可解释尺度。不同单位优先拆为对齐的分面图；必要的双轴必须明确两轴、单位与系列关系，避免暗示不存在的同步性。
- 并排比较的小图默认使用可比的时间范围和数值尺度；若各图独立缩放，只能读各自趋势，并需明显标明，不能让相似曲线暗示相同幅度。
- 堆叠面积适合看总量及构成趋势；比较中间系列的精确变化时改为分面或单独折线。
- 类别太多时用排名加“其他”或可搜索明细；“其他”的合并规则和总量关系应可解释。
- 环形进度只用于读数不需要精细横向比较的少量目标；多个目标比较优先条形进度，超目标值保留真实数值。
- 点阵适合粗略扫读完成量或人员分布，注明每点代表的数量并配汇总值；需精确比较时改用条形或明细，不能让装饰点数冒充真实记录。
- 桑基用于分支与流向探索；固定路径的每步流失用漏斗更直接。没有连接数据时，不能凭各节点总量拼出桑基。
- 地区只有名次差异时用排行；地图不作为填满空白的装饰。颜色表达总量还是率，应根据问题和分母决定。
- 直方图区间边界、散点中的极端值、热图中尚未发生的观察期都不能为了整齐而隐去。
- 流畅曲线、动画和渐变不能改变数值位置、峰值、目标线或选择结果；必要的图例、标签不能只靠悬停显示。

## 4. 建立主区与辅助区

先列“业务问题 → 所需数据 → 表达 → 后续动作”，再安排位置；没有独立问题的模块应合并或删去。

- 主区回答本页最高优先问题；使用图表时给予完整刻度与足够绘图区，使用任务队列或内容卡片时给予识别对象和操作的空间。辅助区解释来源、分组或后果。
- 经营概览可用“结果 → 主趋势/目标差距 → 贡献/异常 → 明细入口”；分析诊断先呈现筛选上下文与主分析。
- 监控页先呈现异常、影响和数据时效；工作台先呈现待办与截止风险。不要机械坚持 KPI 必须在最顶端。
- 专题叙事标题可写有依据的结论；证据不足时用中性主题或问题标题，图表仍保留口径和出处。
- 同级指标使用一致尺寸；只有业务重要性明显不同才扩大某项，不能因为某个数字短就把它做成主角。
- 摘要列表保留识别对象、判断状态和进入明细所需的字段；大规模筛选、分页、批量处理交给列表视图。
- 一个区域有自己的筛选、滚动、操作或独立状态时才考虑独立容器；相近信息可用间距和分隔线分组。
- 不默认加入 AI 助手、欢迎横幅、排行榜或升级推广；只有实际任务依赖它们时才占用首屏面积。

### 将信息关系落成版面

| 主要阅读路径 | 可用构图 | 为什么这样安排 |
| --- | --- | --- |
| 先看结果，再解释变化 | 顶部指标带；下方宽趋势区＋窄贡献区；再下方摘要 | 结果与原因连续，明细不抢占主趋势 |
| 先决定做什么 | 待办/日历主区；侧边截止风险与负载；次要统计靠后 | 操作对象有足够空间，统计服务执行 |
| 先处理异常 | 更新状态与关键异常置顶；事件队列和相关趋势并列 | 选中事件后能立即查看证据和操作 |
| 先找内容 | 搜索与分类置顶；内容卡片或列表主区；选中详情按需展开 | 根据实际内容字段识别对象，不强制插入KPI带 |

这些是构图起点，不是固定列宽和模块清单。主区、辅助区的标题、内边缘和绘图区建立共同对齐；同类卡片重复统一的内部顺序，重点区通过面积和位置突出。窄屏沿同一阅读路径重排。

## 5. 密度与对齐

- 以阅读频率、决策复杂度和对象数量选择密度：汇报重层级，日常分析重比较，监控重状态与处置。
- 先确定导航后的内容起点、主列和辅助列；卡片边缘、标题和绘图区沿少量清晰对齐线组织。
- 多模块可用不等宽网格，主区占较多空间；同一行模块共用起点，不必为追求等高填充无用内容。
- 以项目已有间距、控件、文字尺度构建紧凑或常规变体；不要逐个模块单独压缩字号。
- 密度过高时先删重复指标、减少图例/装饰、把次要内容放到下钻，再调整间距；保留标签与单位。
- 图表空间先满足主数据、轴、标注和交互；标题或筛选多时扩大容器或重排，不能让图形被挤成细条。
- 示例中的数字、列宽和模块数量不是硬规则；内容增多或减少时按主问题重新分配空间。

## 6. 桌面、平板和手机的重排

断点由真实内容开始拥挤的位置决定，沿用项目已有断点；下面是排列原则，不是统一像素规范。

| 屏幕条件 | 排列策略 | 保留什么 |
| --- | --- | --- |
| 宽桌面 | 主区加辅助区；必要时多列指标/对比 | 主图完整刻度、筛选范围、异常与明细入口 |
| 平板/中等宽度 | 减少并列列数，辅助区移到主图后；长筛选分行 | 主要任务顺序与当前选中条件 |
| 手机/窄屏 | 单列任务流，指标按优先级分组，复杂探索进入详情 | 关键数值、异常、单位、周期与主要操作 |

- DOM/阅读/键盘顺序应与任务优先级一致；重排后不要出现视觉第一项却最后才能访问的情况。
- 次要解释、长明细和高级筛选可折叠；异常、必需单位和决定含义的基准不能默认藏起。
- 筛选折叠为面板时，在页面保留已选条件摘要和清除入口；有生效按钮时明确编辑值与已生效值。
- 图表在窄屏减少刻度、缩短显示标签或提供重点系列；保留完整信息入口，不把所有内容等比缩小。
- 多系列图可切换系列、改分面或提供摘要表；需横向比较的表格可局部横滚并保留关键识别列。
- 地图、桑基、复杂日历在手机可先给摘要/列表，再进入专门视图；核心任务不能依赖拖拽或 hover。
- 移动端必须能触发与桌面相同的关键详情与操作，触屏按下不应同时触发两个互斥行为。

## 7. 滚动、长中文与大数字

- 优先使用清晰的页面滚动；只有队列、明细表、日志等需要独立查看时才设置局部滚动，并显示其边界。
- 避免多层嵌套滚动。固定导航、表头或操作栏不能覆盖标题、最后一行、菜单与键盘焦点。
- 中文标题允许自然换行；标签长时增加横向空间、改为上下排或使用说明，不逐字竖排。
- 关键对象名不要只显示省略号；列表可截断并提供触屏/键盘均能访问的全名或详情。
- 大数字采用一致的千分位、精度和单位；需要紧凑显示时标明“万/亿/k”等并提供精确值，避免不同卡片口径混杂。
- 数值与单位保持邻近，金额符号与正负号不能掉到孤立下一行。表格数值按同一规则对齐，可采用等宽数字。
- 对长中文、超大数、负值、零、空值、多标签及较多列表行检查布局；不要只用短英文和整齐样例验证。

## 8. 筛选范围与数据时效

- 区分全页筛选、分区筛选和单图选择；位置、标题或已选条件说明其作用范围，避免用户误以为全页联动。
- 切换门店/大棚/账户时更新所有相关数据与标题。若某模块跨实体汇总，应明确标为全局信息。
- 下钻携带相关时间、实体、人群与选择条件；返回后恢复合理的上下文，不无故清空用户分析。
- 刷新期间可保留旧值，但表明更新中；新旧时间批次混用时标明差异，不能显示“全页最新”。
- 自动刷新保留正在查看的详情、选择和滚动位置；高频队列可暂停更新，并让用户知道有新数据。
- 长时间序列按当前任务选择粒度；聚合时写明每小时/每天及求和、均值等方式，避免平均化隐藏监控尖峰。大量事件使用摘要与可继续查看的队列，不仅显示前几条却暗示已经完整。
- 时间标签使用约定时区和粒度。当天、最近七天、自然周、滚动窗口是不同含义，应让选择文案表达清楚。
- 空筛选、失败、部分更新和过期状态都沿用第 2 节，不让“暂无数据”覆盖所有问题。

当任务包含保存视图、分享或导出时，保留组织/对象、时期、筛选、比较基准与数据截至时间。说明分享的是会继续更新的视图还是固定快照；导出中的标题、单位、图例和必要注释可独立理解。保存布局与保存筛选是不同动作，按实际需要提供，不默认新增全部功能。

## 9. 语义样式值与完成检查

以下只是无现成命名时的可选组织方式；复用项目现有名称，不另建一套重复体系，也不把示例色调写回全局偏好。

| 语义用途 | 可选名称 | 使用关系 |
| --- | --- | --- |
| 表面与边界 | `surface.page`、`surface.panel`、`border.subtle` | 区分页面、模块与必要边界 |
| 文字 | `text.primary`、`text.secondary`、`text.muted` | 次级文字仍需可读，不能用浅色掩盖口径 |
| 交互 | `action.primary`、`selection`、`focus` | 选中、主要操作与焦点有稳定表达 |
| 业务状态 | `status.good`、`status.warning`、`status.critical` | 同时配文字或符号，涨跌依业务方向判断 |
| 数据系列 | `chart.series.*`、`chart.reference`、`chart.target` | 同一指标跨图保持编码，基准和目标有区别 |

交付前确认：主问题与主要内容一致；指标口径和单位可追溯；目标/异常有依据；筛选与数据同步；不同状态可区分；长内容及目标设备可读。仅编写规范时检查这些规则是否明确；实现页面时再检查实际渲染与关键交互，不把未运行的检查写成通过。
