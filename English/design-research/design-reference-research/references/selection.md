# Select a case and preserve its evidence

## Retrieval without preloading

The [index](index.md) is a small human/agent-readable routing table. Use its reviewed cases by page scope, then theme, density, layout, and the unresolved detail. For an exact brand absent from those eight, read only its alphabetic CSV shard. IDs and metadata enums are stable across language editions; explanatory text is localized. `card` paths are relative to the package root. `source_path` identifies the upstream file, not a local runtime path.

With the cluster MCP, use metadata discovery → selected entry → `read_skill_file` for the index and chosen cards. The current MCP catalog searches skill metadata, not case content; CSV files are read resources, not a semantic-search service. A file-capable host may filter the CSV fields locally. No script execution is required. The four shards are bounded so each fits one normal resource read; avoid loading all four for a known brand.

## Decide whether the evidence fits

| Condition | Decision |
| --- | --- |
| Name conveys mood only; direction is sufficiently supported | Continue with the chosen direction without opening the catalog. Describe local design choices as adaptations; do not present uninspected product details as source facts. |
| Borrow a specific visual relationship | Inspect the relevant supplied material or reuse adequate inspected evidence. Research only missing source details needed for the decision; a familiar name is not evidence. |
| Explicit case comparison or source check | Perform the requested scoped research even if the current theme is complete. |
| Faithfully reproduce a supplied target | Keep that target authoritative and inspect it directly. Research only unresolved source questions; a catalog case must not replace the supplied target. |
| Existing theme; local behavior fix | Skip reference research unless requested or needed for a concrete evidence gap. |
| Source research targets a reviewed named brand | Read that card; retain the actual page scope when explaining its applicability. |
| Generic dark developer marketing page | Consider Linear's surface and screenshot relationships; compare only if another unresolved dimension requires it. |
| Operations Dashboard or administrative table | None of the initial eight establishes a complete verified operational workflow. Borrow a narrow visual relationship if useful; let existing page methods own structure and behavior. |
| Consumer marketplace search/detail | Airbnb offers task-relevant document observations; booking outcomes and states still need target-product design and verification. |
| Named brand exists only in the inventory | Report indexed-only/unknown scope. If retrieval tools are available, fetch its pinned source, inspect source scope and gaps before using it; otherwise give the link and continue with available evidence. Do not invent a card or claim offline coverage. |
| No compatible source | State the gap and make a labeled provisional choice or use established project methods. Do not force a famous brand into the task. |

Industry alone is a weak match. An enterprise brand's homepage may be useful for product explanation but provide no evidence for permissions, tables, navigation return state, or chart semantics. Marketing product mockups and `illustrative`/`ex-*` examples remain distinct from observed product surfaces.

## Evidence is per claim

- **Official rule:** only when an actual first-party specification has been inspected. These bundled cases do not establish this class.
- **Third-party observation / claimed extraction:** what the source document reports; exact CSS-like values are not automatically independently measured.
- **Author recommendation:** a suggested fallback, duration, breakpoint, or adaptation. Keep that label.
- **Illustrative / synthesized example:** a demonstration composed from primitives; useful as a candidate, not proof of the brand's shipped UI.
- **Local adaptation:** your proposal for this task, with conditions and tests.

All eight cards have status `document_reviewed_product_unverified`. `indexed_only` confirms identity and pinned source metadata only; its scope and tags stay `unknown`. Unknown interaction, narrow-screen and accessibility coverage remains unknown. Document contradictions require task-level judgment or further inspection, not averaging values.

## Transfer one relationship at a time

State the borrowed relationship and its region, then map its roles onto the existing theme. For example, a dark background → subtly raised panel → visible boundary relationship can use the target product's neutral scale; adopting it does not adopt a lavender brand accent. Keep status, chart and interaction meanings intact.

Choose typography for real content and language support. Large Latin display text with negative tracking does not determine Chinese body spacing. Check target backgrounds, text lengths, available assets, touch/keyboard operation, long labels, loading/error states and narrow layouts when implementation is in scope. Source assertions about contrast or compliance are not completed checks.

Return sources, selected dimensions, rejected mismatches, adaptations and open verification. Advice can end here. A requested project `DESIGN.md` may summarize purpose, direction, source IDs and scope, existing Token location, component decisions and checks; it must not become a separately editable Token authority.
