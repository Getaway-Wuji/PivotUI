# 操作安全、异常状态与返回连续性

## 操作安全与权限

- **读写权限控制**：按项目约定隐藏或禁用无权限操作并给出说明；前端隐藏不等于后端鉴权。
- **破坏性操作**：不可逆删除/归档必须通过 `Modal` 二次确认，写明具体记录名称/编号及影响范围；低风险局部确认可使用 `Popconfirm`（遵循 `floating-components`）。
- **异步防重与恢复**：提交中防止重复触发，操作失败时保留当前页面上下文，持续错误使用 `Alert` 展示（不把 `Toast` 用于承载错误）。

## 异常状态处理

| 状态场景 | 必须覆盖的界面行为 |
| --- | --- |
| 加载中 | 保留框架与页头结构，使用稳定占位/骨架屏减少跳动 |
| 记录不存在或已删除（404） | 明确说明请求的记录编号不可用，并提供返回父列表入口 |
| 无访问权限（403） | 清晰提示权限边界，不泄露敏感字段，提供安全退出路径 |
| 次级关联面板加载失败 | 主记录正常展示，仅在失败的关联面板内提供错误提示与局部重试 |
| 并发过期或编辑冲突 | 覆盖前提示冲突，允许刷新最新数据或对比冲突字段 |

## 返回连续性约定

- 与父列表共享同一权威数据源，确保编辑保存后详情页与返回列表数据一致。
- 通过页内返回或浏览器后退回到来源列表时，由约定的单一返回协调者恢复该历史条目的筛选、页码与滚动位置；若编辑导致记录不再满足原筛选条件，则夹取有效页码、给出原因提示，并将焦点移到可用位置，不聚焦已消失行。
- 不得假定 `window` 是滚动容器，应通过框架暴露的实际滚动容器恢复位置。

## 交付检查项

- 有效 ID 与无效 ID 的直达深链均可正常展示并提供合理出口。
- 列表 → 详情 → 编辑保存 → 返回列表 全链路数据一致、筛选与页码保留正确。
- 窄屏下页头操作与属性分组自然换行堆叠，无横向溢出。
- 键盘遍历覆盖返回入口、主操作、Tabs 与确认弹窗，且焦点清晰可见。
