# 共用方法摘编

仅在目标项目没有对应规范时读取。来源为《界面共用设计规范》0.2 和《自制与外源设计 Skills 联动方案》0.1（2026-11-14），为独立分发提炼；不包含任何产品的默认品牌。

- 围绕使用者的任务组织行为，沿用已有组件、token、文字语气和交互习惯。局部临时选择不自动变成全产品规则。
- 一个页面或区域有一个实现负责人。精细交互负责状态、反馈、焦点、键盘与恢复；页面主力保留布局与业务组织，组件能力承载实现，响应式能力处理输入方式和空间约束。
- 配色、字体、圆角、阴影、时长与曲线优先取目标项目现有值。缺失时只补当前需要的局部默认值，记录为暂定。公共变化交由主控归并到该产品唯一的可维护来源。
- 只给任务涉及的控件补适用状态。状态信息同时用文字、形状或图标表达；保证焦点可辨与操作有名称。
- 加载、空数据、无匹配、请求失败、权限不足有不同含义。表单失败保留输入；提交给出结果；影响显著的操作提供与影响匹配的确认或撤销。
- 键盘可完成主要流程；触屏有与悬停、拖拽相适应的可达入口。动效帮助理解变化，并响应减少动态效果偏好。
- `gpt-taste` 只用于对外营销区域。该边界不禁止后台使用服务任务的轻量反馈，也不禁止合适的 React Bits 组件。
- 普通辅助模块缺失时直接完成必要工作，说明实际使用范围。不要虚构已调用某个 skill 或已完成检查。
- 参考图可证明可见样式；动态、设备和请求行为需要相应证据。规则验证与运行检查分开记录。
