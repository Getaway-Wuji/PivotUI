# 输入能力、高度与溢出

局部修复，或布局变化影响控件访问时读取。宽度与输入能力彼此独立：窄桌面窗口可以使用键盘和鼠标，大屏也可以支持触屏。

## 保持操作可用

有意义的操作应有明确控件，并显示键盘焦点。悬停可以增加预览或强调，但不能是显示必要信息或激活操作的唯一方式。`hover`／`pointer` 描述主要输入；`any-hover`／`any-pointer` 考虑可用输入。混合设备可能同时具有粗略和精细指针。不要依据这些查询推断有无键盘，也不要据此移除键盘访问。[输入特性语义](https://www.w3.org/TR/mediaqueries-4/#mf-interaction)。

使用已有触控目标和间距，或在容易指向不准时有目的地扩大命中区域。相邻目标保持可区分，防止透明命中区域相互覆盖。对于检查 WCAG 2.2 AA 的项目，SC 2.5.8 规定 24 × 24 CSS 像素的目标，或符合其列明的例外（包括间距）；这不是通用的推荐按钮尺寸。[目标尺寸准则](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

响应式收纳与展开中，区分持续的选中／打开状态和临时悬停。当前控件在切换时消失，要保留有效的焦点去处。非活动的重复控件不能进入焦点与无障碍导航。与现有交互负责人协调 Modal／Drawer 的焦点管理、Escape 行为和焦点返回。不要仅为节省宽度就把标签换成没有说明的图标。

## 从根源诊断溢出

1. 用实际内容和失效的视口或容器复现问题。确定溢出属于页面、组件，还是有意设置的滚动区域。
2. 检查最先超出可用尺寸的元素及其祖先尺寸链：固定／最小宽度、Flex/Grid 自动最小尺寸、`white-space`、长字符串、媒体尺寸、内边距加宽度、`100vw`、变换或定位装饰。比较边界与滚动尺寸；有意放在画布外或隐藏的元素可能造成误报。
3. 修复最小的责任范围。常见情况是 Flex/Grid 项需要 `min-width: 0`／`min-inline-size: 0`，弹性轨道需要 `minmax(0, 1fr)`，或子项需要换行、自己的有边界滚动。沿嵌套祖先定位，而不是随意增加断点。
4. 普通内容换行。只对不可断行的引用等内容选择性使用 `overflow-wrap: anywhere`；避免全局 `word-break: break-all` 损害正常阅读。限制媒体尺寸并保留宽高比。[换行行为](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow-wrap)。
5. 内容含义依赖宽度时，使用局部滚动区域，并在需要时提供清楚名称或说明。检查指针、触屏和键盘的横向访问；目标浏览器需要时才添加可聚焦性，不要让每个包装层都成为 Tab 停靠点。防止新增滚动边界裁切焦点轮廓或已打开菜单。
6. 重新检查原失效案例、相邻布局状态、内容完整性和主要操作。页面主体没有溢出并不单独代表成功。

仅对有意超出的装饰使用裁切，且裁切不得移除意义、焦点或命中目标。不要用全站 `overflow-x: hidden` 修复问题。有意设置的 Modal 页面主体滚动锁是另一种行为，必须可靠解除。

## 视口高度与内容增长

同时考虑高度和宽度：横屏、浏览器控件、缩放、展开的错误和屏幕键盘，都可能令可用内容空间很少。`svh` 代表小视口，`lvh` 代表大视口，`dvh` 代表动态视口；依据任务更需要稳定容纳，还是跟随变化的浏览器界面来选择。动态单位不是虚拟键盘的通用修复，键盘可能覆盖内容而不改变这些值。[视口单位定义与注意事项](https://www.w3.org/TR/css-values-4/#viewport-relative-lengths)。

内容可能增长时，优先使用由内容决定的高度或适当最小高度，而不是刚性的满高容器。保留到达焦点字段和提交操作的滚动路径。测试项目实际浏览器与键盘行为；安全区域内边距处理设备／界面边缘，不能解决所有键盘遮挡。为支持的浏览器范围提供回退，并保留用户缩放能力。不要设置限制缩放的 viewport 标志来制造布局稳定的表象。
