# 查询与返回

## 状态约定

分别维护输入草稿、已应用查询、展示偏好、选择和任务状态。实用的查询约定包含筛选／搜索、稳定排序、页码或游标、每页条数，以及 API 使用的数据版本。明确哪些状态可放入 URL 共享，哪些属于会话或用户偏好；避免把敏感查询值放入 URL 或大范围共享存储。

| 事件 | 必须确定的处理 |
| --- | --- |
| 应用不同搜索／筛选 | 提交查询，回到其首个有效页，并清空或明确核对调整选择 |
| 重置查询 | 恢复定义好的查询默认值；不悄然重置无关的列／视图偏好 |
| 改变排序或每页条数 | 展示新排序／条数，选择有效位置，并明确选择保留策略 |
| 翻页 | 保留已应用查询；区分本页选择与其他页保留的 ID |
| 收到旧请求响应 | 忽略／取消旧响应，防止其替换当前查询结果 |
| 数据量减少 | 调整到有效页码或游标，说明调整原因，并保留查询 |

行键及操作使用稳定记录 ID，不用行索引。服务端排序／分页必须与计数、筛选覆盖同一结果集合；仅对已加载页排序不能呈现为全局排序。使用稳定的同值排序依据。对于游标 API，应保留可用游标并说明失效情况，不虚构 API 无法支持的精确页码。

## 结果状态

首次加载、后台刷新、没有数据、没有匹配结果、无权访问和加载失败需要不同呈现。无匹配与失败时保留已应用筛选的可见性。无匹配状态可清除相关条件；初始空数据可在有权限时提供新建／导入；无权限状态说明可用的权限申请路径，但不泄露隐藏记录。刷新失败时可以保留旧行并标注过期。不能把失败或无权限请求显示为零条结果。

为失败保留持续可见的错误／重试区域，并保留用户输入。谨慎选择播报语义；更新不应抢走焦点或播报每次按键。只有属于当前查询的响应才能更新数量和分页。

## 详情往返

导航前记录已应用筛选、排序、页码／游标及每页条数、相关视图／列、稳定的来源记录 ID，以及页面／局部滚动锚点。若未完成输入需要保留，应单独保存草稿。使用产品路由／历史或限定范围的状态存储，让浏览器“后退”和可见返回链接同样有效。明确持久化期限；不能仅依赖组件持续挂载。

返回时：

1. 在请求或渲染列表前恢复查询／展示状态。按产品数据时效规则刷新，同时保留已恢复的上下文。
2. 数据到达后确定有效页和来源记录。目标存在后再恢复滚动与焦点；设置焦点时控制滚动，避免破坏已恢复的位置。
3. 如果删除、权限变化或重新排序使来源记录不再位于原处，使用最近的合理记录或结果标题作为落点，说明变化并保留其余查询上下文。不盲目恢复失效操作或选择。

直接访问详情而没有列表历史时，需要可预测的列表回退路由。返回目标应限定为经过校验的站内地址。从详情返回不能重新执行已经完成的批量任务。是否恢复选择由产品单独决定：保留时重新检查符合条件的 ID 并展示范围；清空时说明。

测试已筛选的后续页、改变后的排序／每页条数、浏览器“后退”、可见返回控件，以及来源记录被移除的情况。输入框内容未变，不能单独证明查询、页码和位置已经恢复。
