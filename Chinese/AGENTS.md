# 界面设计 Skill 集群

界面任务使用 [design-orchestrator](orchestration/design-orchestrator/SKILL.md)，只加载相关模块。已有明确分工的局部任务可直接进入对应模块。仅选择本语言版本的技能；中英文版本使用相同名称。

创建或修改设计 Skill、共用规范或路由前，先读 [FOUNDATIONS](design-system/FOUNDATIONS.md) 与 [ORCHESTRATION](design-system/ORCHESTRATION.md)。普通界面任务只读取相关约束。沿用目标产品已经确认的视觉决定，用户当前明确要求优先。

- MCP 可用时先发现元数据，再读取选中入口和指定资源；否则直接按同样规则读文件，不预加载整套集群。
- 每个区域设置一个实现主力。Token 属于目标产品，保持单一权威来源；全局风格模块生成与校验，主控汇总结果。
- 复用已有组件与行为，在设计实现过程中纳入交互和响应式要求。普通缺失模块由执行者补齐，不声称调用了不可用 Skill。
- `gpt-taste` 只用于对外营销，不用于 Dashboard 或业务工具；`ui-ux-pro-max` 仅研究与建议。使用外源前先读取实际入口。
- 区分临时风格选择与用户确认偏好。需要跨窗口接续时，在目标项目现有模块记录中保存参考依据、采用特征、局部范围和验证结果。
- 修改前重读文件。并行工作分开文件范围，共享修改统一协调。产品全局视觉变更写回产品记录；通用方法变更才写入本库。
- 分发 Skill 保持自包含。使用包内相对引用，不带个人路径、制作中间文件和不需要的原始参考整包；较长的条件式指导放在按需参考中。
- 核心和业务入口保持精简。原 500–2000 个中文汉字预算是编写指导，不是英文字符上限，也不是所有模型的通用最佳长度；保留必要行为。
- 同时维护两套时，先改英文再同步对应中文，保持标识与行为一致。只有一套可用时记录待翻译事项，不把另一套变成运行依赖。
- 按功能在语言根目录下建立分类，同类内源与外源包放在一起。在 README.md 记录来源和上游署名，保留原作者命名与声明，不增加按来源划分的目录。先发现元数据，再按需读取分类中的入口。
- 检查元信息、资源链接、实际改变的行为和分发内容。区分已经执行的检查与尚未执行的运行或视觉检查。
