# 选择案例并保留证据性质

## 无需预加载的检索

[索引](index.md)是便于人和代理阅读的小型路由表。先按页面范围选已审读案例，再看主题、密度、布局和待解决细节。明确品牌不在这八项中时，只读取其所在的字母分片 CSV。ID 和元数据枚举在两套语言版本中保持稳定，说明文字本地化。`card` 路径相对于包根目录；`source_path` 指向上游文件，不是本地运行资源路径。

使用集群 MCP 时，按元数据发现 → 选定入口 → `read_skill_file` 读取索引与所选卡片。当前 MCP 目录搜索 Skill 元数据，不搜索案例正文；CSV 是可读资源，不是语义搜索服务。可操作文件的宿主可以在本地筛选 CSV 字段。无需执行脚本。四个分片均限制在单次常规资源读取范围内；已知品牌时不要读全四片。

## 判断证据是否适合

| 条件 | 决策 |
| --- | --- |
| 已有主题；局部行为修复 | 除非用户要求或存在明确证据缺口，否则跳过参考研究。 |
| 用户指定已审读品牌 | 读取对应卡片；解释适用性时保留真实页面范围。 |
| 常规深色开发者营销页 | 可考虑 Linear 的表面与产品截图关系；只有其他维度仍待解决时才增加比较。 |
| 运营 Dashboard 或管理数据表 | 首批八项都不能证明完整且已核验的运营工作流。需要时借鉴局部视觉关系，结构和行为交给现有页面方法。 |
| 消费者市场搜索/详情 | Airbnb 提供与任务相关的文档观察；预订结果和状态仍需目标产品自行设计并验证。 |
| 指定品牌仅存在于目录 | 说明仅登记、范围未知。若有读取工具，可获取固定版本原文，先检查来源范围与缺口再使用；否则提供链接并利用现有证据继续。不编造卡片或声称已离线覆盖。 |
| 没有相容来源 | 说明缺口，给出标注为暂定的选择，或使用项目既有方法。不强行套用知名品牌。 |

仅按行业匹配依据不足。企业品牌首页可能适合产品说明，却没有权限、数据表、导航返回状态或图表语义证据。营销产品展示图与 `illustrative` / `ex-*` 示例始终区别于观察到的真实产品页面。

## 按具体说法区分证据

- **官方规则：**只有实际查阅第一方规范后才能使用此类别。随包案例不建立此类证据。
- **第三方观察／声称提取：**来源文档所报告的内容；看起来像精确 CSS 的值不自动成为独立实测值。
- **作者推荐：**建议的替代字体、时长、断点或适配，保留推荐标签。
- **演示／合成示例：**由基础值组合的演示，可作为候选，不证明品牌已上线该 UI。
- **本地适配：**你针对当前任务的提案，注明条件和检查。

八张卡片均为 `document_reviewed_product_unverified`。`indexed_only` 只确认身份和固定版本来源元数据；其范围与标签保留 `unknown`。未确认的交互、窄屏和无障碍覆盖仍为未知。文档内部矛盾需要任务层判断或补充查证，不取平均值解决。

## 每次迁移一个明确关系

说明借鉴关系及适用区域，再把角色映射到既有主题。例如，深色背景 → 略微提亮面板 → 可见边界的关系，可以使用目标产品自己的中性色阶；采用它不等于采用薰衣草色品牌强调。保持状态、图表和交互的既有含义。

排版以实际内容和语言覆盖为依据。带负字距的大号拉丁展示字不能决定中文正文字距。任务包含实现时，检查目标背景、文案长度、可用资产、触控/键盘操作、长标签、加载/错误态和窄屏布局。来源的对比度或合规声称不等于已完成检查。

返回来源、选用维度、排除的不匹配内容、适配和待验证项。建议可以止于此。用户要求的项目 `DESIGN.md` 可总结用途、方向、来源 ID 和范围、已有 Token 位置、组件决策及检查；它不能成为另一套独立可编辑的 Token 权威来源。
