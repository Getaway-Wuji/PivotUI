# Retro Web

Source: supplied board 02, label **Retro Web**. Dimension: historical interface references and nostalgic illustration. This is a candidate, not a product default.

## Observed evidence

The example borrows browser-window framing, gray beveled panels, blue underlined links, small pixel illustrations, and desktop-like chrome. These are visual references to older interfaces. The screenshot cannot establish real window management, browser behavior, or keyboard conventions.

## Suggested adoption

Consider this for nostalgic portfolios, cultural projects, game communities, or a deliberately themed campaign. Select a coherent set of recognizable conventions rather than mixing unrelated eras. Use real links and buttons beneath the treatment. Mark decorative title bars and status details as visual content instead of implying unavailable browser or system functions.

## Combinations and constraints

Combine with `pixel` for imagery or `minimalism` to keep content manageable. Avoid reproducing obsolete interaction limitations: retain usable touch targets, current keyboard access, clear focus, and meaningful navigation. Dense work tools generally need a quieter treatment than a simulated desktop full of overlapping windows. Small bitmap lettering should not carry long instructions.

## Assets, cost, and fallback

CSS framing is inexpensive; a complete desktop simulation is a separate, larger scope. Prefer static decorative chrome unless window behavior is actually requested. On narrow screens, fall back to stacked panels with ordinary navigation while retaining a few recognizable retro accents.
