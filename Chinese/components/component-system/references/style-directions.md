# 选择方向，保留外观差异

参考外观影响组件决策时读取。以下是对用户参考的作者归纳，不是通用预设，也不代表已经完成运行验证。[来源地图](source-map.md)说明证据及局限。

## 按用途比较

| 方向 | 适用情况 | 可借鉴的组件规则 | 应保留的差异 |
| --- | --- | --- | --- |
| 克制的产品控件 | 高频操作、设置、列表、表单 | 优先级清楚，文字/图标对齐稳定，适度表面层级，密度协调；焦点与错误可读 | BoardUI 的细边框/轻渐变和 Apple 平台约定不要求所有控件扁平、玻璃化或使用同一圆角 |
| 成熟产品组合 | 成长中的产品需要跨页面稳定组件家族 | 组成明确、区域可组合、变体用途清楚、受控值与事件可预测 | HeroUI 或企业库的 API 名称与框架要求仅属于对应库/版本 |
| 细腻局部反馈 | 复制、保存、选择、展开、状态变化 | 过渡中保持对象身份与上下文；反馈对应真实事件；保留标签及当前值 | Bencho 式形变、图标、时长和动作依任务决定；先补齐失败与复位路径 |
| 有表现力的展示 | 产品亮点、发现卡片、突出操作或详情揭示 | 局部层级、材质或动效可加强，但附着于稳定语义结构 | beUI、Aceternity、Rare UI 及画廊作品各有处理方法；只为所选区域采用合适的一种 |
| AI / 未来感状态呈现 | 生成、搜索、语音或异步任务 | 动效绑定真实状态，保留状态文字及取消/重试路径，隔离装饰渲染 | Orb、边缘光、金属、流体、shader 均是候选，不能定义所有 AI 界面或成为必选主题 |
| 高密度企业任务 | 重复比较、大型表单、批量操作 | 行与控件密度协调、稳定标识、有效状态、明确选择及数据归属 | Ant、Arco、TDesign、Element、Semi 的框架和约定不同，按已安装技术栈与任务选择，不设强制排名 |

不同方向可在明确命名的区域共存。营销亮点与管理表格可以共享品牌 token，同时采用不同强调和密度。局部特效不能通过基础 Button 或 Card 悄悄扩散到整个产品。

## 从单份参考提炼可复用规则

1. 找到真实组件与任务，排除展示边框、截图说明和无关页面装饰。
2. 描述必需/可选部分和阅读顺序，记录相对关系，如标签对齐、内边距一致、次级文字小于操作标签。精确尺寸需要源码或测量依据，否则标为估计。
3. 将任务语义与外观分开：开关设置、提交请求和已完成操作不会因动画相似而变成同一种任务。
4. 写出带条件的规则，例如“有明确默认操作及相关备选项时使用分裂式操作”，或“高频桌面列表使用更紧凑且控件配套的行”。不同条件下有效的方案应保留。
5. 将选定处理映射到现有 token 与公共 API，再放回真实内容与设备场景检查。

来源中漂亮的默认态不能证明禁用态、对比度、触摸目标、键盘访问、异步正确性或性能。分别记录观察、来源声明和补充方案，验证当前任务真正需要的部分。

## 限定效果范围，保留有用反馈

纹理、光晕、玻璃、shader 与粒子属于可选视觉层。它们不能拦截关键输入、遮挡焦点、降低文字可读性，也不能决定操作是否成功。当减少动态效果、图形能力不可用或目标设备需要时，保留可工作的静态呈现。采用开销较大的效果时检查挂载/卸载清理及按可见性执行的工作，不把 GPU 效果强加给普通业务控件。

声音可选，遵循产品音频偏好与交互设计。点击声和成功声对应不同事件。静音或浏览器禁止音频时，关键反馈仍完整可用。避免重复绑定、自动修改全局音量以及流式输出逐 token 发声。声音库不要求新建另一套操作组件。

Brand Archive、Minimal Gallery、Footer、Happy Hues 分别支持所选品牌、布局、分组或颜色角色问题。页面结构归页面主力，全局品牌选择归全局风格/主控。这些案例不提供组件 API，也不能成为复制整套视觉系统的理由。
