# 完整数据列表页设计

让查找记录、处理记录和继续原有工作形成连贯流程。负责完整列表区域及其业务语义。Dashboard 中的小表格或局部控件修复不自动触发整套流程。

## 确立工作约定

结合已给任务和现有产品，确定实体、用户的主要决策、识别与比较字段、可用操作、权限、数据规模、查询 API、设备，以及继承的应用框架、组件和 Token 来源。直接补齐常规缺口；仅在缺失的业务规则会改变结果时提问。按工作需要选择功能：保存视图、批量操作和导出都是可选能力，不要求每页全部具备。

用户指定的参考方向为：

> 数据列表页布局参考 Ant Design Pro 列表页：顶部筛选栏、表格上方批量操作按钮、列设置开关、页面底部分页。从详情页返回后保留筛选状态和页码。

将其作为结构参考和必须实现的工作连续性要求。它不确定固定品牌、技术栈或像素规格，也不证明上游已经实现这些行为。编排页面或解释该参考时，读取[布局与参考](references/layout-and-reference.md)。

## 先定义列表，再实现

围绕识别、比较和下一步操作组织页面。沿用产品密度和文字样式；保证长内容可读，避免次要元信息抢占重点。区分查询控件、表格与视图控件、依赖选择的任务和行操作。

明确一次查询对应哪些记录、当前选中了什么、操作会影响哪些对象，以及导航后保留什么状态。本页复选框不能悄然代表全部匹配记录；查询变化不能悄然扩大先前的选择。详情返回必须保留已应用的筛选条件与页码，并恢复有用的位置。

## 集成与完成

主控选择本模块作为列表区域负责人。复用目标产品的应用框架和 Token。`component-system` 负责 Table 和公共控件实现；本模块负责页面组合及业务约定。`interaction-design` 及相关子入口补充尚未覆盖的行为；`responsive-design` 补充跨屏缺口；`global-style-skill` 处理实际主题缺口。每个组件指定一名实现负责人。直接复用已有且满足要求的行为；支持技能缺失时，由当前执行者完成常规缺口。

交付所需规格或可操作页面，说明采用的来源、状态与范围决策、组件归属和实际检查。在目标项目已有记录中分别记载观察、估计与补充设计。实现时用真实渲染和输入验证相关流程；标明演示数据并如实列出未运行检查。独立包范围与来源见 [PACKAGE](PACKAGE.md)。
