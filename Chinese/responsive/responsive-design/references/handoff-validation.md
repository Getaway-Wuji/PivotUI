# 交接与验证

协调响应式修改或检查结果时读取。复用当前任务记录；小型局部修复只需记录相关决定。

## 与负责人的约定

| 输入／输出 | 内容 |
| --- | --- |
| 接收 | 区域与用户目标；视觉方向和 token 来源；组件；目标设备、浏览器范围和输入预期；已有断点；参考用途；允许的修改 |
| 布局前提出 | 条件与优先级；保留内容；重排方式；操作延续；已观察与补充设计的区别 |
| 实现时协调 | 将组件变体和受影响调用方交给 `component-system`；将触屏、键盘、焦点、悬停和状态切换交给 `interaction-design`；每个区域一名整合者 |
| 完成后返回 | 修改文件／区域、采用条件、保留状态与访问路径、验证证据、剩余局限，以及需要统一整合的共享修改 |

页面负责人拥有业务优先级的决定权；响应式工作将其转为可用的排列。共享 token 提案仍由主控／全局风格负责人处理。不要悄悄创建另一套断点或 token 来源。独立使用本模块时，在许可范围内承担这些角色，并按需读取[可移植约定](foundations.md)。缺少专家模块不应阻止普通工作。

发现能力时，定位实际 `responsive-design` 入口。使用技能集 MCP 时，先查看元信息目录，再加载入口和选定的链接资源；没有 MCP 时，读取声明的文件位置。候选名称出现在列表里并不证明它可用。本包不强制依赖技能集其他部分，也不要求额外注册格式。

## 检查实际界面

按受影响区域选择检查，不固定罗列所有设备：

1. 覆盖约定的目标宽度和高度。每个已实现的布局切换都检查实际阈值略低于、等于和略高于的位置，并在切换后每种布局中选一个代表性宽度。依赖容器时，独立于视口宽度改变该容器。
2. 尝试真实的长标题、翻译标签、URL、数字、空值／缺失值，以及相关加载和错误状态。在支持时验证文字放大与浏览器缩放。堆叠后保留有意义的源顺序、阅读顺序和焦点顺序。
3. 同时检查意外的页面溢出和有意的局部滚动。确认完整值、必要列、图表含义和移动后的控件仍可访问。在低高度及内容展开后检查 fixed／sticky 区域。
4. 使用键盘与可用指向输入完成适用的关键操作：开关导航、筛选、查看详情、选择行、开关浮层、提交和错误恢复。面板打开或表单／选择仍活动时改变尺寸，验证状态延续和有效焦点位置。
5. 记录实际环境、视口／容器尺寸、阈值、内容／状态、操作和观察结果。保留相关证据，报告失败并在范围内修复，随后仅重复受影响的检查。

对于重排无障碍检查，WCAG 2.2 SC 1.4.10 为纵向滚动内容使用 320 CSS 像素条件（例如，从 1280 CSS 像素起始宽度放大到 400%）。必要的二维区域有例外，但其周围页面不因此豁免，也不免除内容可访问义务。将其视为测试条件，不是设计断点或完整无障碍认证。[重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。

## 准确报告证据

| 证据 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 规则审查／场景推演 | 指导是否能支撑所需决策和交接 | 实际渲染行为或浏览器兼容性 |
| 构建／生成 CSS 检查 | 对应工具链中的语法和生成规则可用性 | 布局可用或交互成功 |
| 浏览器视口检查 | 在已记录设置下观察到的渲染与已执行交互 | 物理触摸准确性、设备键盘或真实移动浏览器界面 |
| 浏览器触控模拟 | 实际执行过的模拟事件与设置 | 真机人体工学或操作系统／浏览器行为 |
| 真机检查 | 已记录设备、操作系统／浏览器、方向和实际操作 | 其他全部设备和浏览器 |

只编写技能时，检查规则、链接和代表性行为决定，不声称完成浏览器或真机验证。未提供可运行页面时，将目标宽度与交互检查标为计划。用户要求实现且存在可运行目标时，应检查该目标，而不是止步于检查清单。

## 代表性编写检查

用三类任务检验模块：仅有桌面参考的官网布局；涉及比较与批量操作的业务表格／图表；包含长内容的窄容器局部溢出修复。评估技能是否保持范围、视觉继承、任务可达性、证据边界和明确整合负责人。使用独立请求，不只检查规定措辞是否出现。将已执行结果放入作者记录，不作为运行时依赖。
