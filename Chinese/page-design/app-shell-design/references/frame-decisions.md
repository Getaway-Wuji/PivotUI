# 框架决策

新建外壳、结构改版，或有具体未解决的路由／空间／滚动问题时读取。选择相关章节，不将其作为每个局部修复都必须执行的全套清单。

## 1. 区分位置与呈现

以产品的路由定义和权限为准。用稳定的路由标识或明确匹配规则映射导航，避免用子串匹配混淆相似路径。详情和编辑路由可以共用可见的导航祖先，无需为每条记录增加侧栏项。

| 路由示例 | 导航位置 | 面包屑 | 标题／页面操作 |
| --- | --- | --- | --- |
| /orders | 订单 | 工作区 / 订单 | 订单 / 创建订单 |
| /orders/:id | 订单 | 工作区 / 订单 / 记录名称 | 记录名称 / 编辑 |
| /orders/:id/edit | 订单 | 工作区 / 订单 / 记录名称 / 编辑 | 编辑记录 / 保存、取消 |

这些用于说明语义，不规定路由名称。不可导航的祖先可显示为文字。不要虚构指向不存在或无权访问页面的链接。未知路由采用产品的未找到页面行为，不显示错误的当前导航项。面包屑表达层级；返回操作表达访问历史或明确的返回目的地。

仅在导航成功后更新当前位置。将 current、hover、focus、展开的分组和已选中的页内 Tab 作为不同状态。进入时展开当前路径的祖先，让多层页面位置可发现；允许用户主动收起，同时不误表示路由已改变。分组标签同时具有跳转和展开功能时，使用两个可区分的控件。

沿用既有权限处理。隐藏导航链接不等于访问控制；授权仍由产品负责。保留深链接、重新加载和浏览器后退／前进的有效路径。

## 2. 确定框架及其边界

依据任务与参考选择空间布局：

- 持续显示的侧栏适合在有层级的工作区域之间反复切换。
- 顶部导航适合较少的同级目的地；混合布局需要明确区分全局区域与局部区段。
- 专注型编辑器可以减少持续显示的导航，前提是产品已有清晰出口和保留状态的返回方式。
- 路由 Tab 是可选项。不因参考是后台脚手架就增加多标签工作台。

采用所给经典模式时，将通栏顶部 Header 放在侧栏和右侧内容区之上，除非目标产品已采用其他 Header／侧栏关系。Header 承载身份／账户和跨页面控件。页面专属操作放在页面标题旁或约定的页面插槽中，不要反复移入全局 Header。

为面包屑、标题和内容确立一条主要左对齐线。记录有意设置的例外，例如流式表格页中的限宽阅读表单。同级页面使用相同的外侧内边距和标题布局；内容模块控制内部列和密度。框架装饰应从属于工作内容。需要区分区域时使用分隔线或表面变化，避免每一层都再套一个带边框的卡片。

侧栏宽度依据标签可读性与层级，内容宽度依据工作需求，Header 高度依据其控件。长标签可换行，或提供可访问的完整标签展开方式；纯图标导航也必须能被键盘和触屏用户理解。具体尺寸、颜色、字体和圆角来自产品 Token 或明确的样例选择，不来自假定的通用脚手架标准。

## 3. 先分配滚动，再固定元素

用简表说明各区域、纵向／横向滚动负责人、持续显示元素和溢出行为。对于本参考模式：

| 区域 | 行为 |
| --- | --- |
| 全局 Header | 位于主滚动容器之外，持续可见 |
| 侧栏 | 保持原位；菜单超出可用高度时，菜单自身纵向滚动 |
| 右侧内容 | 负责页面主要纵向滚动 |
| 宽表格或其他局部内容 | 可负责局部横向滚动；不意外创建第二个纵向视口 |
| 页面标题 | 随内容滚动，除非任务确有理由采用吸顶变体 |

通过 grid／flex 容器也能让元素保持原位，不要求字面使用 CSS `position: fixed`。框架尺寸适配可用视口空间，允许 grid／flex 子元素收缩，避免 body 滚动条与预期内容滚动条竞争。如果产品原本使用文档滚动，保留该模式并相应定义 sticky 边界。

考虑持续显示的 Header／操作区高度、滚动偏移、安全区域、缩放，以及适用时的屏幕键盘。菜单和浮层不能被局部溢出边界裁切；与现有组件系统协调层级／portal 规则。短高度下检查最后一个导航项和最后一个页面操作。不要用整页裁切有用内容来解决溢出。

## 4. 保持导航与工作连续

每次转换都明确保留什么、由谁恢复：

- 列表 → 详情 → 列表：筛选、排序／页码、适用时的选择、滚动，以及用记录 ID 标识的来源控件。
- 详情 → 编辑 → 详情：记录身份与有意义的上下文；草稿、保存／取消和未保存变更策略由页面／表单负责人处理。
- 直接进入详情／编辑：没有已知的应用内返回上下文时，使用有效的层级目的地。不要盲目调用 history.back() 将用户送出应用。
- 收起或调整尺寸：保留当前路由与工作状态。在隐藏包含焦点的元素前，将焦点移到可见控件。

先使用路由器已有的状态／恢复设施，再考虑另建存储。将返回上下文保存在合适的历史条目或路由实例范围内，不让无关页面共用一个全局滚动值。来源行已不存在时，恢复列表上下文，并聚焦仍存在且有意义的标题或控件。

原生链接保留预期导航和修饰键行为。展开按钮应准确声明展开状态与受控对象；隐藏的后代退出 Tab 顺序。沿用已有页面切换焦点管理；实际路由变化可以聚焦页面标题，单纯展开菜单不能抢走内容焦点。提供可到达的内容入口，例如产品已有的跳过导航链接。

## 5. 在无法继续容纳时调整

复用产品断点；没有既定断点时，找出真实标签、页面操作或内容开始无法容纳的位置。桌面侧栏变窄和移动端导航打开是不同状态。保留用户的桌面折叠偏好，不将其强加到移动端体验。

按需要使用已有的紧凑导航栏、可展开面板或重新安置的导航。如果导航采用模态方式，完整实现焦点限制、背景 inert、关闭／Escape 和焦点返回；如果采用非模态方式，保留自然的文档导航。窄视口并不自动要求使用 Drawer 组件。选择路由后关闭临时导航，并将焦点置于新内容入口。定义导航打开时视口变化的处理方式。

检查每个转换点附近，而不只检查一个桌面尺寸和一个手机尺寸。即使桌面宽度充足，短高度也可能需要可滚动导航和非吸顶的页面操作。长译文和放大文字下保持控件可用；不要缩小整个界面来强行容纳。
