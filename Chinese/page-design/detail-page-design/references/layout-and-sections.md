# 详情页布局与分区

## 页头结构

置于应用框架内容标题插槽内：

1. **返回入口与面包屑上下文**：从列表进入时返回原列表历史条目；直达深链时提供可靠的父列表返回路径。
2. **主身份区**：记录名称、可复制的稳定编号（等宽数字）以及当前生命周期状态标签（颜色与文字并存）。
3. **关键摘要元信息**：最多 3–5 项高信号信息（负责人、更新时间、优先级、金额/数量），让用户在滚动前先确认未打开错记录。
4. **操作区**：明确唯一主操作（如编辑、审批），次要操作收敛，破坏性操作放入更多菜单或视觉隔离区并配确认机制。

## 纵向分区、Tabs 与侧栏摘要选型

| 记录复杂度 | 推荐结构 | 注意事项 |
| --- | --- | --- |
| 轻量实体（1–3 组字段、无重型子表） | 单栏或两栏描述网格 + 纵向分组卡片 | 不足 3 个实质子域时避免滥用 Tabs |
| 中等实体（主体属性 + 动态/摘要） | 宽屏主内容列（明细 + 关联子表）+ 侧边摘要/动态栏 | 窄屏按阅读优先级自然折叠，不隐藏关键信息 |
| 复杂实体（概览、明细项、账单、审计日志等独立子域） | 固定身份页头 + Tabs 切换子域 | 同步选中 Tab 到路由状态；关键异常 Alert 置于 Tabs 之上 |

## 字段排版规则

- 金额、数量、编号与时间戳启用等宽数字（`tabular-nums`）。
- 严格区分明确零值（`0`）、空值/未填（`—`）、脱敏值与加载中状态。
- 兼容超长名称、多行备注与多标签，防止截断关键字段或把操作按钮挤出可视区。
- 关联子表保持轻量聚焦；若子表需要完整筛选、批量任务与导出管理，应跳转至 `data-list-design` 负责的完整列表视图。
