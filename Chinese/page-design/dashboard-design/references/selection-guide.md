# 按需求选择 Dashboard

本文件是从参考归纳并补充的选型方法；A–G 编号为本 skill 创建，不是来源中的原分类。来源编号的含义见 [方法摘要](reference-index.md)，视觉方案见 [visual-recipes.md](visual-recipes.md)。下列规则可以直接使用，无需原始图片。

## 先判断主任务

以下问题是候选判断，不是按顺序命中第一条就结束。先用角色、访问目的、处理时限和主要操作确定哪项占主导。

1. **持续值守、及时确认与处理事件是否是主要工作？** 是：C。趋势和汇总为处置提供背景；普通经营页出现异常摘要，不因此自动变成监控页。
2. **主要是完成任务／安排人员？** 是：D。不要让待办沉在几排 KPI 下。
3. **主要是解释原因、比较分组或探索维度？** 是：B。
4. **主要是发现和打开内容对象？** 是：F。内容卡片或列表比 KPI 墙更合适。
5. **主要查看某个账户、资源池或个人状态？** 是：E。
6. **主要向读者讲清一项发现／成果？** 是：G。
7. **主要快速判断整体经营情况？** 选择 A。

这些问题可以同时成立，用本次角色的最高优先任务确定主结构；副任务进入次级区或下钻。用户只是要批量维护记录时，直接建议以数据列表为主，不为满足 Dashboard 名称硬加图表。

容易混淆的情况：老板每天看退款异常但由运营处理，通常仍是A；值班员要及时接手事件才以C为主；一线人员按截止时间完成工作是D；分析师调查指标变化是B；已有明确发现、主要向他人解释证据时是G。同一套数据可服务不同视图。

选完再检查数据条件：缺少分组数据时保留概览、取消分组分析；缺少路径边时把桑基改为已有步骤的转化表达。核心指标尚未接入时标明待接入，不能把页面主任务改成“只展示当前容易获得的数据”。

## 七种结构配方

### A 经营概览

- **适用**：管理者、电商负责人、SaaS 经营、销售主管、门店负责人。
- **要回答**：现在表现怎样？离目标多远？哪里贡献／拖累最大？
- **结构**：标题+组织/时间范围 → 少量核心结果 → 一张主趋势/目标图+结构解释 → 重点异常或业务摘要。
- **候选**：P02、P04；需讲述结论时 P01；温和产品用 P03。参考 S16、S26、S29、V04。
- **数据条件**：核心指标的实际值、单位与时间范围；目标、可比历史和业务分组按已具备数据选配，不因没有其中一项就放弃经营概览。
- **动作**：从异常/分组进入有相同筛选上下文的明细。
- **避免**：每个部门占同样面积；十几个 KPI 一字排满；用总量掩盖转化或利润恶化。

### B 分析诊断

- **适用**：增长、产品行为、渠道效果、留存、销售构成、专业分析。
- **要回答**：变化从哪里来？哪一组不同？发生在路径的哪一步？
- **结构**：维度/人群/周期 → 主分析视图 → 同期/分组/路径比较 → 对应记录或解释。
- **候选**：P01、P02、P04；深色项目用 P05。参考 S26–S30、V08。
- **数据条件**：所选分析所需的维度、粒度与时间窗口；比例需要分母与样本量，路径需要连接关系。只有总量时不能推导原因或分群。
- **动作**：筛选、选择区间、切维度、查看明细、清空选择；联动范围可见。
- **避免**：用桑基图代替简单排行；不同分母的转化率直接并列；无数据却生成因果结论。

### C 实时监控与处置

- **适用**：服务/设备/库存/生产/多站点值守、客服运行状态。
- **要回答**：哪里异常？影响多大？数据是否新鲜？下一步找谁处理？
- **结构**：刷新与连接状态 → 严重异常/受影响对象 → 趋势及阈值 → 有优先级的事件队列。
- **候选**：沿用已有明暗主题；P04 或 P05；少数独立业务区可用 P07。参考 S05/V01 的运营分区、S30、V08；告警机制是本 skill 的补充。
- **数据条件**：时间戳、更新状态、观测对象；处置队列还需事件状态、影响范围及负责人/分派信息。告警级别或阈值由实际规则提供；尚未配置时标明该限制，不发明等级。
- **动作**：查看对象、确认/分派事件、临时暂停滚动；具体权限由项目决定。
- **避免**：数据跳动改变排序和焦点；自动数字从零计数；用翻面藏告警；用品牌橙色同时代表普通选中和最高告警。

### D 任务与团队工作台

- **适用**：项目协作、设计团队、CRM 跟进、招聘、个人日程、场务。
- **要回答**：我现在该做什么？哪里会延误？资源是否够用？
- **结构**：待办/风险与下一步 → 时间线、日历或任务队列主区 → 进度/负载 → 最近协作。
- **候选**：P03、P04、P10；明确展示诉求可 P09。参考 S14、S19、S09、S12、S36、V05。
- **数据条件**：任务标识、状态和下一步；协作时需负责人，排期时需截止日期，依赖或容量按实际功能选用。
- **动作**：打开任务、调整计划、快速新建；拖拽应有非拖拽替代。
- **避免**：用“完成率”和排行榜挤掉待办；所有团队都添加排行榜；只切菜单高亮而内容不变。

### E 账户与资源概览

- **适用**：账户余额、现金流、云存储/配额、个人健康记录、设备资源概况。
- **要回答**：我拥有什么／处在什么状态？变化怎样？最近发生了什么？
- **结构**：主余额/容量/状态+常用动作 → 流入流出/使用变化 → 构成或目标 → 近期流水/事件。
- **候选**：P02、P03、P06；低密度品牌首页可 P11；资源展示可 P09。参考 S15、S17–S18、S32、V03、V07。
- **必要数据**：币种/容量/指标单位、时间、总量与子项关系、授权范围。
- **动作**：查看明细、进入资源管理或已有业务操作；不把金融或医疗样例变成行业建议。
- **避免**：异币种未经换算相加；余额与收入混同；把缺失健康数据显示为正常；直接复制示例健康判断。

### F 内容与资源发现

- **适用**：素材库、作品、课程、行程、媒体内容、资产预览。
- **要回答**：有哪些对象？哪一个适合我？怎样快速打开／继续？
- **结构**：搜索分类 → 推荐/最近对象 → 图片/内容卡片流 → 选中对象摘要或上下文。
- **候选**：P08，清淡框架；信息管理量大时改列表为主。参考 S37、V02。
- **数据条件**：对象标识与名称、任务需要的属性；图片、状态和推荐信息按真实字段选配，缺图时有一致替代。“最近访问”需要访问记录，修改时间不能代替打开时间；素材、项目等对象类型来自数据字段或明确集合，不能凭封面猜测。字段缺失时如实改为“最近修改”等可支持的表达。
- **动作**：筛选、打开、继续浏览、收藏（需求有才加）。
- **避免**：装饰照片无业务含义；长标题被彻底截断；质量差的图片成为整页主要视觉。

### G 专题叙事与成果报告

- **适用**：经营月报、研究概览、能源/可持续成果、面向阅读者的专题页。
- **要回答**：最值得理解的发现是什么？证据在哪里？范围和进展如何？
- **结构**：真实结论或中性主题标题 → 关键证据 → 主图 → 原因分解/目标进展 → 来源与详情入口。
- **候选**：P01、P06；数据精读时 P02。参考 S26、S31、V06。
- **数据条件**：结论所需证据、时期和数据出处；涉及比较或目标时再核对基准和目标口径。
- **动作**：查看口径、比较时期、展开证据、导出（有需求时）。
- **避免**：为了写“大标题”虚构发现；用自然配色暗示数据结论；用仪表圈代替缺失的目标。

| 需求中的实际任务 | 主结构 | 推荐表达 | 首选视觉/来源 |
| --- | --- | --- | --- |
| 老板看本月销售和利润 | A | 核心结果与趋势；有对应数据时再加同期比较、目标、贡献排行 | P02/P04；S16/S29 |
| 电商运营找转化下降原因 | B | 同期趋势、漏斗、渠道/设备比较、异常明细 | P01/P04；S26/S28 |

| 项目经理分配下周工作 | D | 截止风险、时间线、负载、任务 | P03/P04；S14/S19 |

## 决策冲突怎么处理

- **品牌要求玻璃 + 密集报表**：保留背景或导航的材质；表格/图表采用近不透明底、固定对齐和清晰标签。
- **深色专业感 + 低对比**：增加表面、边界、文字的区别，减少发光；主题不替代可读性。
- **多指标 + 小屏**：重排任务优先级、提供分组或下钻；不缩小全页到手机里。
- **想要惊艳 + 要高效操作**：把表达集中在主图或一个关键区域；常用控件保持稳定。
- **不确定选哪套**：交付一套有理由的主方案，只有取舍明显时再给备选；不要让用户先从十一种风格中盲选。

## 再判断展示载体

展示载体与A–G任务结构分别选择。“大屏”不自动等于深色监控，“手机”也不是把桌面等比缩小。

| 使用方式 | 如何调整同一任务结构 |
| --- | --- |
| 桌面工作界面 | 支持比较、筛选、详情与操作；密度依熟练度和内容量确定 |
| 手机处理工作 | 先放本角色当前任务、异常和主要动作，复杂分析进详情；已选范围可见 |
| 远距离墙屏／会议展示 | 减少并列内容，直接显示关键标签、单位和刷新时间；关键状态不依赖鼠标或触摸，实际观看距离决定字号 |
| 静态报告／导出 | 明示时间、筛选范围和数据截至时间；将悬停内容改为直接标签或图注；去掉不能执行的控件 |

墙屏只有确需轮播时才轮播，关键异常不随轮播消失。需要远程处置时提供明确的工作端入口，不能把只读展示误作可操作台。
